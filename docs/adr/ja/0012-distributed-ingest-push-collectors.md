# ADR-0012: 分散インジェスト — コレクターが gRPC + mTLS でコアへプッシュする

- **Status:** accepted
- **Date:** 2026-06-04
- **Deciders:** Fran Olivares (boot decision CB-1)
- **References:** roadmap boot decisions (CB-1 → option C); runtime-ingestion contract

## コンテキストと課題

インジェストプレーンにはトポロジーの決定が必要だった。コレクターは顧客のホスト上で観測し、
コアが集約する。選択肢は、インプロセスのみから完全に分散したプッシュモデルまでにわたり、
隔離・ネットワーク信頼境界・パッケージングへの影響を伴った。

## 意思決定の要因

- データプレーンを顧客インフラ上に保ち、ネットワーク越えを堅牢化する。
- 単純なケースのために単一バイナリを維持する。
- コレクターの依存関係をコアから隔離する。

## 検討した選択肢

- **C — リモートプッシュ:** コレクターがソースコネクターをローカルで実行し、観測結果を
  **gRPC + mTLS** でコアへ**プッシュ**する。コレクター側に**インバウンドのリスナーを
  持たない**。
- **B — アウトオブプロセスのローカル:** コネクターをローカルのサブプロセスとして実行
  （AutoMTLS）。単一ノードの基盤（substrate）。
- **A — インプロセス:** ソースをバイナリにリンクする（ファーストパーティのファストパス）。

## 決定の結果

選択した選択肢: **C（リモートプッシュ）を分散のターゲットとし**、B を単一ノードの基盤、
A をファーストパーティのソース向けインプロセス・ファストパスとして保持する。すべての
トランスポートが v1 に入り、C は**先送りしない**。仕組みはランタイムに存在し、分散
パッケージング（DaemonSet/Helm）はサプライチェーン作業とともに提供される。

### 帰結

- **良い点:** データはネットワーク境界を堅牢化された状態で越える（mTLS + bearer + authz）。
  コレクターはインバウンドポートを公開しない。単一バイナリが維持される。
- **悪い点 / トレードオフ:** 分散デプロイメントでは可動部分が増える。
- **中立:** 単一バイナリのデフォルトは、インプロセス / ローカルサブプロセスの経路を使う。

## 代替案を却下した理由

- **A** も **B** も単独ではマルチホストのスケールをカバーしない。それぞれファストパスと
  単一ノードの基盤として保持されるのであり、分散の答えとしてではない。
