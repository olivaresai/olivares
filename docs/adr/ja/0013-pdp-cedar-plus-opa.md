# ADR-0013: 認可 PDP — Cedar の組み込み + OPA-over-HTTP アダプター

- **Status:** accepted（restrict-onlyは、この記録で作成された
  `auth.PolicyEvaluator` シームの範囲に限定）— **ADR-0019
  (2026-06-15) により修正**。ベース permit が削除され、このオーバーレイが
  黙って無効化していたオペレーターの permit ルールが実際に許可するようになり、
  Cedar 自体も別のシームで肯定的かつスコープ付きの grant エンジンへ変更された。
  forbid のみのポリシーは影響を受けない。以下の「背景」と「意思決定の要因」にある
  「決して拡大しない」という記述は、そのような読み方については失効している —
  末尾の修正追記を参照。
- **Date:** 2026-06-04
- **Deciders:** Fran Olivares
- **References:** NHI/MCP-auth contract; ADR-0019 (Cedar scoped grants) により修正

## コンテキストと課題

RBAC を超えて、本プラットフォームには属性ベース認可のための policy decision point（PDP、
ポリシー決定点）が必要である。組織はさまざまである。自己完結したエンジンを望む者もいれば、
既存の OPA エステート（estate）を持つ者もいる。PDP はアクセスを決して*拡大*してはならず、
制限するのみでなければならない。

## 意思決定の要因

- 外部のポリシーサービスなしで、自己完結（単一バイナリ、air-gap）で動作する。
- オペレーターが既存の OPA デプロイメントを持つ場合、それに適合する。
- 制限のみ（restrict-only）の不変条件: ポリシーは拒否できるが、RBAC を超えて付与しない。

## 検討した選択肢

- **両方:** Cedar の組み込み（主、純 Go）**と** OPA-over-HTTP アダプターを単一のシーム
  （seam）の背後に置き、オペレーターが選択する。
- **Cedar のみ。**
- **OPA のみ。**

## 決定の結果

選択した選択肢: **両方を、単一の `PolicyEvaluator` シームの背後に置く**。**Cedar** は
組み込み・純 Go の主たる PDP であり、**OPA-over-HTTP** アダプターも利用可能である。
オペレーターは `OLIVARES_PDP_ENGINE = cedar | opa | none` でエンジンを選択する。ABAC
シームは**制限のみ**を行う（RBAC と AND を取り、決して拡大しない）。制限のみの不変条件は
エンドツーエンドでテストされる。

### 帰結

- **良い点:** デフォルトで自己完結（Cedar、サイドカー不要）。望めば OPA エステートに
  適合する。単一のシーム、二つのエンジン。
- **悪い点 / トレードオフ:** 二つのアダプターを保守する必要がある。OPA 経路のトランス
  ポート堅牢化（例: サイドカーへの mTLS）は文書化された拡張であり、まだ完成していない。
- **中立:** `none` は ABAC レイヤーを無効化し、RBAC の deny-by-default（デフォルト拒否）を
  残す。

## 代替案を却下した理由

- **Cedar のみ** — OPA に標準化した組織を除外してしまう。
- **OPA のみ** — すべてのインストールに外部のポリシーサービスを強制し、自己完結 /
  air-gap のデフォルトを壊してしまう。

## 修正追記（2026-06-15、ADR-0019）

*（修正した決定の日付は 2026-06-15 である。この追記は、11 日差で署名された 2 つの
記録間に優先関係を示すリンクがないことを決定登録の点検で発見した 2026-08-17 に
追加された。上記の文章は書き換えていない。）*

**記述どおりではなくなったこと。** 「背景」の *「PDP はアクセスを決して拡大せず、
制限するのみ」* と「意思決定の要因」の *「ポリシーは拒否できるが、RBAC を超えて付与しない」*
は、記述どおりに読めば **認可判断全体** と **Cedar** に関する記述である。
**ADR-0019** 以降、その読み方ではどちらも正しくない。Cedar は deny-only の
オーバーレイから 3 値のスコープ対応 **grant** エンジンへ格上げされ、Cedar の判断を
restrict-only にしていた暗黙のベース `permit` が削除されたため、作成された `permit` が
現在は実際に許可を付与する。

**代わりに正しいこと。** restrict-only 不変条件は、**この記録が作成したシームに
限定された形で**存続する。`auth.PolicyEvaluator` は依然として RBAC の後に実行され、
さらなる制限のみを行える（`core/auth/authorizer.go:100-104`）。肯定的な grant は
**別の新しい**シーム `auth.ScopedAuthorizer` にあり、deny オーバーレイの中ではなく、
その **横に** 配線されている。Authorizer は両者を
`Allow = (RBAC ∨ Grant) ∧ ¬Forbid ∧ ¬deny-overlay` として組み合わせる
（`core/auth/authorizer.go:157-163`、代数式は `:161` と `:200`）。deny-by-default、
forbid-overrides-permit、およびエラー時の fail-closed は維持される。作成済み grant のない
デプロイメントは、この記録の下での判断と完全に同じである。その他のすべては引き続き
成り立つ。1 つのシームの背後にある 2 つのエンジンと
`OLIVARES_PDP_ENGINE = cedar | opa | none` セレクターが、実際に出荷されている動作である
（`cmd/olivares/wire.go:994-1018`）。

**現行の決定が記録されている場所。** `docs/adr/0019-cedar-scoped-grants.md`
（accepted、2026-06-15、Fran Olivares）であり、そこでこの記録を明示的に参照している。
*ABAC* という用語からたどり着くこの ADR のみを引用した読者は、出荷された肯定的 grant 経路が
署名された決定に違反すると結論するかもしれない。しかし違反はなく、ADR-0019 に従っている。
