# ADR-0020: Enterprise エディションを別の非公開リポジトリから配布する

- **Status:** accepted
- **Date:** 2026-06
- **Deciders:** Fran Olivares
- **References:** ADR-0010 (license is attestation-only), ADR-0011 (license boundary),
  `LICENSING.md`

## 背景と課題

ライセンスモデルはオープンコアである。AGPL の core/modules/web が完全なコミュニティ
エディション、SDK/connectors が Apache-2.0、`enterprise/` 系統が ADR-0011 に従い
`-tags enterprise` でのみビルドされる追加的な商用コードである。しかしこれまでは、
`enterprise/` のソースが**公開リポジトリ内で配布されていた**。有効化ゲートはビルドタグであり
（ADR-0010 によりアテステーション専用であるライセンスではない）、ライセンスはランタイムを
一切ゲートしないため、誰でも `git clone && go build -tags enterprise` を実行して完全な商用
バイナリを無料で取得できた。商業的な防壁は、可視で自由にコンパイルできるソースに対する法的
ライセンス（名誉方式）だけに依存していた。

## 意思決定の要因

- ビルドタグによるゲーティングを見せかけではなく**実効的**にする。公開ソースだけから誰でも
  商用バイナリをコンパイルできる状態にしてはならない。
- AGPL コミュニティバイナリを**ビット単位で変更しない**。すでにオープンに配布されたものから
  機能を取り上げず、ラグプルを行わない。
- ディレクトリ単位のライセンス境界（ADR-0011）とアテステーション専用ライセンス
  （ADR-0010）を、どちらも変更せず維持する。

## 検討した選択肢

- **`enterprise/` を公開リポジトリに残す**（GitLab の単一リポジトリ内 `ee/` モデル、
  source-available）。誠実ではあるが、防壁は可視で自由にコンパイルできるソースに対する
  名誉方式にすぎない。
- **`enterprise/` を別の非公開リポジトリへ移す**（Grafana モデル: 公開 OSS ソース +
  非公開ソースからビルドされたダウンロード可能な enterprise バイナリ）。

## 決定の結果

選択した案: **`enterprise/` を別の非公開リポジトリへ移す**。公開リポジトリには、
`enterprise/` ツリー、`//go:build enterprise` の `cmd/olivares` 配線、または
`-tags enterprise` をビルドするツールを含めない。商用バイナリは、公開ツリーの固定された
checkout に商用ツリーと配線を重ね合わせて非公開リポジトリ内でビルドする（公開ツリーは
submodule であり、配線は `cmd/olivares` の `package main` にオーバーレイされる。
`go.work` のモジュール選択だけではこれは実現できない）。

これはライセンスではなく**配布**だけを変更する。

- **ADR-0011（ライセンス境界）は変更なし:** `enterprise/` は引き続き
  `LicenseRef-Olivares-Commercial` であり、AGPL/Apache の境界は維持される。
- **ADR-0010（アテステーション専用ライセンス）は変更なし:** オープンバイナリは引き続き、
  機能の有効化・無効化のためにライセンスを読み取らない。ライセンスが*実質的な*意味を持つのは、
  アテステーションされた claim（add-on entitlements）を読み取るソースが非公開になったためだけで
  あり、ライセンスがランタイムをゲートし始めたためではない。

### 帰結

- 公開リポジトリの `git clone` + `go build -tags enterprise` では、必要なソースが非公開で
  あるため、商用バイナリを生成できなくなる。ゲーティングは実効的になった。
- デフォルトの AGPL バイナリは変更されない。もともと `enterprise/` をリンクしていない。
- open≡enterprise schema-parity gate（両エディションを必要とする）は、両方をビルドできる
  唯一のツリーである非公開リポジトリへ移る。
- 2 つのリポジトリと小さな overlay assembly step がコストとなる。公開リリース成果物は影響を
  受けない（すでに `-tags release` でビルドされ、`-tags enterprise` ではなかった）。

## 改訂 (2026-07-28) — 上で述べた座席の権利付与はなくなった

配布に関する決定は有効である。`enterprise/` は非公開リポジトリにあり、ビルドタグによる
ゲーティングは実効的である。もはや成り立たないのは「アテステーションされた claim（座席の
権利付与）を読むソース」という「帰結」で用いた*例*である。決定 B10（2026-07-27）により
ユーザー上限が撤廃されたため、座席の権利付与は存在せず、どのビルドもユーザーを上限設定する
ためにライセンスを読まない。残るアテステーション済み claim は、追加的な add-on の権利を
付与するためだけに読まれる。元の文は、この ADR が決定された時点で真実だったことを記録する
ため、そのまま残す。現在の決定: 商用価格カノン（非公開で管理）
（`self_hosted.users: unlimited`）および `LICENSING.md`。
