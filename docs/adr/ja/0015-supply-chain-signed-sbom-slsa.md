# ADR-0015: サプライチェーン — 署名付きリリース、SBOM、SLSA プロベナンス、OpenVEX、distroless

- **Status:** accepted
- **Date:** 2026-06
- **Deciders:** Fran Olivares
- **References:** stack decisions (T6/T7); supply-chain & release-verification design

## 背景と課題

セキュリティ製品にとって、署名されていない、あるいは検証不可能なリリースは許容できない。購入者は
*自分がダウンロードしたもの* を検証する必要があり——完全にオフラインの air-gapped（隔離）環境を
含めて——あらゆるアーティファクトのプロベナンスと既知脆弱性の状態を把握する必要がある。

## 決定の要因

- すべてのアーティファクトの暗号学的な検証可能性（オンラインおよびオフライン）。
- プロベナンス（誰が、どのソースからビルドしたか）とソフトウェア部品表（SBOM）。
- 最小限でダイジェスト固定されたランタイムイメージ。

## 検討した選択肢

- **cosign/sigstore 署名 + SBOM（syft）+ SLSA Build L3（SLSA v1.2）プロベナンス + OpenVEX +
  ダイジェストで固定された distroless イメージ**。オフライン検証経路と
  air-gap バンドルを備える。
- **チェックサムのみ／署名なしのリリース。**

## 決定の結果

選択した選択肢: **完全なサプライチェーンセット**。リリースには cosign 署名、SPDX +
CycloneDX SBOM、SLSA Build L3 プロベナンス、OpenVEX アテステーションが付属する。コンテナイメージは
**distroless であり、ダイジェストで固定されている**。検証スクリプトがチェーン全体を確認し、
**完全にオフライン**のモードも含む。**air-gap バンドル**は公開鍵を運び、切り離された
サイトが透明性ログなしですべてを検証できるようにする。

### 帰結

- **良い点:** すべてのアーティファクトはオンライン・オフラインを問わず検証可能。プロベナンスと
  SBOM が各リリースに付属する。ランタイムイメージは最小限かつ（ダイジェストにより）不変である。
- **悪い点／トレードオフ:** 維持すべきリリース機構が増える。air-gap バンドルでは
  SBOM/VEX/プロベナンスをバンドラーに供給する必要がある。
- **中立:** デプロイは常にダイジェストで行い、決してタグでは行わない。

## 代替案を却下した理由

- **チェックサムのみ／署名なし** — プロベナンスも、オフラインの信頼の起点も、
  脆弱性に関する言明も提供しない。セキュリティ製品では許容できない。

## 追記（2026-07-03）：SLSA v1.2 の表記と Source トラックの評価

SLSA の表記を **SLSA Build L3（SLSA v1.2）** に統一する。SLSA v1.2 では
Build トラックの最上位が L3 であるため、この ADR が主張するのは Build トラックの
そのレベルのみである。

Source トラックの評価は別に扱う。Source L1–L3 には、保持されたソースリビジョンと、
ソース管理システムからのプロベナンス・アテステーションが必要となる。Source L3 にはさらに、
たとえば gittuf またはプラットフォーム・アテステーションによる、継続的かつ改ざん証拠を
残す強制が必要となる。

現状：ブランチ保護は `scripts/apply-branch-protection.sh` でスクリプト化されているが、
ソース・プロベナンスのアテステーションはデプロイされていない。

決定：Source トラックのレベルは主張しない。Source トラックを注視し、公開ローンチ時に再検討する。
