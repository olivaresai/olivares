# ADR-0014: GitHub Actions + Docker による公開リリースと CI

- **Status:** accepted
- **Date:** 2026-06-04
- **Deciders:** Fran Olivares (boot decision)
- **References:** roadmap boot decisions (Release/CI)

## 背景と課題

開発はプライベートリポジトリで行われるが、公開された検証可能なサプライチェーンには、
広く信頼され透明性のある CI/リリース基盤が必要である（キーレス署名のアイデンティティ、
SLSA プロベナンス、公開アーティファクト配布のため）。

## 決定の要因

- 公開され検証可能なリリースアイデンティティ（OIDC）と、署名のための透明性ログ。
- 標準的で広く信頼されたコンテナ配布。
- リリースがキュレーションされ公開されるまで、日々の開発をプライベートに保つこと。

## 検討した選択肢

- **すべての公開アーティファクトに GitHub Actions + Docker を使用し、開発はプライベートリポジトリで行う。**
- **公開リリースについても自己ホスト型 CI を使用する。**

## 決定の結果

選択した選択肢: **公開するものはすべて、常に GitHub Actions + Docker を使用する**。**開発は
プライベートリポジトリで行う**。リリースワークフローの GitHub Actions OIDC
アイデンティティが、キーレス署名と SLSA プロベナンスが証明する対象であり、イメージ/チャートは
公開 OCI レジストリに公開される。

### 帰結

- **良い点:** 署名とプロベナンスが、公開され検証可能なアイデンティティに連なる。標準的な
  配布。意図的に公開されるまで開発はプライベートに保たれる。
- **悪い点／トレードオフ:** 公開リポジトリは、プライベートな開発リポジトリのキュレーションされた
  エクスポートであり、ライブミラーではない。
- **中立:** 公開リポジトリの公開は、意図的でゲート付きのアクションである。

## 代替案を却下した理由

- **公開リリースに自己ホスト型 CI** — 自己ホスト型の署名アイデンティティは、透明性ログを伴う
  公開された GitHub Actions OIDC アイデンティティよりも、第三者が検証するのがはるかに困難である。
