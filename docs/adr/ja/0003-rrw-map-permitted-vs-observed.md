# ADR-0003: Permitted-vs-Observed の差分を備えた R/RW map は、差別化された主要な機能である

- **Status:** accepted
- **Date:** 2026-06-02
- **Deciders:** Fran Olivares
- **References:** product decisions register (P2); architecture (module III)

## 背景と課題

多くのツールはエージェントのアクティビティを*観測*でき、また多くのツールは付与された権限を
*列挙*できる。だが、いずれか単独では、ガバナンスにとって本質的な問いに答えられない。すなわち、
**あるエージェントが*許可（permitted）*されている対象は、*観測（observed）*されている対象と
同じなのか？** という問いだ。製品には、これに答える、防御可能でコモディティ化しにくい機能が
必要だった。それは製品が提供する複数の機能の 1 つであって、製品全体ではない。

## 意思決定の要因

- コモディティ化しにくく、セキュリティ／SOC にとって直接的に有用な機能であること。
- 製品が実際に取得できるシグナル（監査、テレメトリ、カーネル）から構築されること。
- 過大な主張をせず、忠実度（fidelity）について正直であること。

## 検討した選択肢

- read/write access map 上での **Permitted-vs-Observed 差分**（least-privilege drift）。
- **Observed のみ** — エージェントが行ったことを示す。
- **Permitted のみ** — 付与された権限を示す。
- **セッションの閲覧** — ライブのエージェントセッションを示す。

## 決定の結果

選択した選択肢：**Permitted-vs-Observed 差分を備えた R/RW access map（module III）**。製品は、
あらゆる origin→resource のエッジについて read/write を分類し、シグナルソースと信頼度を記録し、
宣言された付与（grants）を観測された使用と差分（diff）することで、**least-privilege drift** を
浮かび上がらせる。すなわち、想定外のアクセス、未使用の付与、そして reconciliation 保留中の
エッジである。

### 結果として生じること

- **良い点：** プラットフォームのガバナンスがその上に構築する、他のモジュールと並ぶ、特徴的で
  セキュリティ上重要なアーティファクトである。単独の機能ではない。
- **悪い点／トレードオフ：** 確かな帰属（attribution）のためにはエージェントごとの ID に依存する
  （共有サービスアカウントでは*近似的（approximate）*な信頼度に落ち込む）。カバレッジはストアごとに
  **段階的（tiered）**である。確実性を捏造するのではなく、`unknown` と `approximate` について正直で
  なければならない。
- **中立的な点：** access map は一般データモデル上の*ビュー*であり（ADR-0005 を参照）、別個の
  スキーマではない。

## 代替案を却下した理由

- **Observed のみ／Permitted のみ** — それぞれは絵の半分にすぎない。価値は*差分*にある。
- **セッションの閲覧** — コモディティ化している（各ベンダーが「エージェントビュー」を出荷している）。
  持続的な堀（moat）ではない。
