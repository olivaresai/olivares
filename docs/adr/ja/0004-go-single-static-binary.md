# ADR-0004: エンジンは Go、web を埋め込んだ単一の静的バイナリ

- **Status:** accepted
- **Date:** 2026-06
- **Deciders:** Fran Olivares
- **References:** stack decisions register (T1, T5); stack architecture

## 背景と課題

セルフホスト可能で air-gap（エアギャップ）に適したセキュリティ control plane は、デプロイが極めて
容易で、eBPF/OpenTelemetry/クラウドネイティブのエコシステムにネイティブであり、単一の
アーティファクトとして出荷可能でなければならない。エンジンの言語も、UI の配信方法も、いずれも
そこから導かれる。

## 意思決定の要因

- セルフホストおよび air-gap のための、自己完結した単一のアーティファクト。
- ネイティブな eBPF と、成熟したモジュール／プラグインのランタイム。
- ingest とイベントバスのための強力な並行性（concurrency）。

## 検討した選択肢

- **Go**、単一の静的バイナリ、`go:embed` 経由で埋め込んだ web。
- **Rust** エンジン。
- **Node/TypeScript** エンジン。
- 埋め込み UI の代わりに **独立した SPA**（2 つのアーティファクト）。

## 決定の結果

選択した選択肢：**Go**。単一の静的バイナリにコンパイルし、React の web UI を **`go:embed` 経由で
埋め込み**、API と同一オリジンから配信する。これにより、製品全体が **1 つのファイル**となる。

### 結果として生じること

- **良い点：** 出荷・検証・実行すべき単一のアーティファクト。ネイティブな eBPF。優れた
  クラウドネイティブとの適合。ingest に適した並行性。
- **悪い点／トレードオフ：** UI はバイナリのビルドの一部としてビルドされ、埋め込まれる。
- **中立的な点：** Node/TypeScript は web UI にのみ使用され、エンジンには使用されない。

## 代替案を却下した理由

- **Rust** — ビルド／反復が遅く、v1 のニーズには過剰である。
- **Node/TS エンジン** — eBPF の対応が乏しく、たとえ快適な領域であっても単一の静的バイナリには
  ならない。
- **独立した SPA** — デプロイとバージョン管理すべきアーティファクトが 2 つになる。埋め込み UI は
  それを 1 つに保つ。
