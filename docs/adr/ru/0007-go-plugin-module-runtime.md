# ADR-0007: Внепроцессная среда выполнения модулей/коннекторов через go-plugin (gRPC)

- **Status:** accepted
- **Date:** 2026-06
- **Deciders:** Olivares AI
- **References:** stack design (module runtime); license-boundary design

## Контекст и постановка проблемы

Платформа должна позволять собственным и сторонним коннекторам и модулям расширять её
без втягивания их деревьев зависимостей в движок и без загрязнения
пермиссивной экосистемы коннекторов copyleft-лицензией движка.

## Факторы, влияющие на решение

- Изоляция зависимостей коннекторов от сборки/SBOM движка.
- Стабильный, версионируемый контракт через границу процессов.
- Сохранение чистоты границы коннекторов на Apache-2.0 (коннектор никогда не линкуется с AGPL-движком).

## Рассмотренные варианты

- **`hashicorp/go-plugin` поверх gRPC** для внепроцессных модулей/коннекторов, плюс
  скомпилированные модули ядра внутри процесса.
- **Только внутрипроцессные плагины** (пакет Go `plugin` или скомпилированные внутрь).

## Принятое решение

Выбранный вариант: **`hashicorp/go-plugin` (gRPC)** для внепроцессных коннекторов/модулей,
при этом собственные коннекторы встроены и запускаются как изолированные подпроцессы, а модули
ядра скомпилированы внутрь. SDK коннекторов — это интерфейс Go плюс версионируемый
контракт gRPC/protobuf.

### Последствия

- **Хорошо:** зависимости коннектора не попадают в бинарный файл/SBOM движка;
  граница Apache/AGPL остаётся чистой и обеспечивается в CI; сторонние разработчики могут поставлять
  коннекторы независимо.
- **Плохо / компромиссы:** контракт gRPC, который надо версионировать, и IPC-переход для внепроцессных
  компонентов.
- **Нейтрально:** единый бинарный файл по-прежнему встраивает собственные коннекторы (изолированные в
  подпроцессах), так что остаётся одним артефактом.

## Почему альтернативы были отклонены

- **Только внутрипроцессно** — втягивает зависимости каждого коннектора в движок и делает
  границу лицензий невозможной для механического контроля.
