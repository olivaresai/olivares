# ADR-0015: Цепочка поставок — подписанные релизы, SBOM, происхождение SLSA, OpenVEX, distroless

- **Status:** accepted
- **Дата:** 2026-06
- **Принявшие решение:** Fran Olivares
- **Ссылки:** решения по стеку (T6/T7); проектирование цепочки поставок и верификации релизов

## Контекст и постановка проблемы

Для продукта в области безопасности неподписанный или непроверяемый релиз недопустим.
Покупателям нужно проверять, *что именно они скачали* — в том числе полностью офлайн, в
изолированных (air-gapped) средах — и знать происхождение и статус известных уязвимостей
каждого артефакта.

## Факторы решения

- Криптографическая проверяемость каждого артефакта, онлайн и офлайн.
- Происхождение (кто собрал, из какого исходного кода) и спецификация состава ПО (SBOM).
- Минимальный, закреплённый по digest рантайм-образ.

## Рассмотренные варианты

- **Подписи cosign/sigstore + SBOM (syft) + происхождение SLSA Build L3 (SLSA v1.2) + OpenVEX +
  образы distroless, закреплённые по digest**, с офлайн-путём верификации и комплектом
  для air-gap.
- **Только контрольные суммы / неподписанные релизы.**

## Итог решения

Выбранный вариант: **полный набор для цепочки поставок**. Релизы поставляются с подписями
cosign, SBOM в форматах SPDX + CycloneDX, происхождением SLSA Build L3 и аттестациями OpenVEX;
контейнерные образы — **distroless, закреплённые по digest**. Скрипт верификации проверяет всю
цепочку, включая **полностью офлайн** режим, а **комплект для air-gap** несёт публичный ключ,
чтобы отключённая площадка могла проверить всё без журнала прозрачности.

### Последствия

- **Хорошо:** каждый артефакт проверяем, онлайн или офлайн; происхождение и SBOM поставляются
  с каждым релизом; рантайм-образ минимален и неизменяем (по digest).
- **Плохо / компромиссы:** больше релизной обвязки в сопровождении; комплект для air-gap
  требует, чтобы SBOM/VEX/происхождение были переданы сборщику комплекта.
- **Нейтрально:** развёртывание всегда по digest, никогда по тегу.

## Почему альтернативы были отклонены

- **Только контрольные суммы / неподписанные** — не дают ни происхождения, ни офлайн-корня
  доверия, ни заявления об уязвимостях; недопустимо в продукте безопасности.

## Дополнение (2026-07-03): формулировка SLSA v1.2 и оценка трека Source

Формулировка SLSA приведена к виду **SLSA Build L3 (SLSA v1.2)**. В SLSA v1.2
трек Build заканчивается на L3, поэтому этот ADR заявляет только уровень трека Build.

Оценка трека Source остаётся отдельной. Для Source L1–L3 требуются сохранённые
ревизии исходного кода и аттестации происхождения от системы управления исходным
кодом; Source L3 дополнительно требует непрерывного, обнаруживающего подделки
принуждения, например gittuf или аттестаций платформы.

Текущее состояние: защита ветвей описана в
`scripts/apply-branch-protection.sh`, но аттестации происхождения исходного кода
не развёрнуты.

Решение: уровень трека Source не заявляется; следить за треком Source и вернуться
к вопросу при публичном запуске.
