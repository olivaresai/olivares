# ADR-0003: Карта R/RW с diff «разрешённое против наблюдаемого» — ключевая дифференцированная возможность

- **Status:** accepted
- **Дата:** 2026-06-02
- **Принявшие решение:** Fran Olivares
- **Ссылки:** реестр продуктовых решений (P2); архитектура (модуль III)

## Контекст и постановка задачи

Многие инструменты умеют *наблюдать* активность агентов, и многие умеют *перечислять*
выданные разрешения. Ни то, ни другое по отдельности не отвечает на вопрос, важный для
governance: **совпадает ли то, к чему агенту *разрешено* прикасаться, с тем, к чему он
*наблюдаемо* прикасается?** Продукту нужна была защищённая, трудно превращаемая в
ширпотреб возможность, отвечающая на этот вопрос, — одна из нескольких, которые он
предлагает, а не весь продукт.

## Движущие факторы решения

- Возможность, которую трудно превратить в ширпотреб и которая напрямую полезна для
  безопасности/SOC.
- Построена из сигналов, которые продукт реально может получить (аудит, телеметрия,
  ядро).
- Честность в отношении достоверности вместо завышенных заявлений.

## Рассмотренные варианты

- **Diff «разрешённое против наблюдаемого»** (отклонение от наименьших привилегий,
  least-privilege drift) поверх карты доступа на чтение/запись.
- **Только наблюдаемое** — показывать, что делали агенты.
- **Только разрешённое** — показывать выданные разрешения.
- **Просмотр сессий** — показывать живые сессии агентов.

## Принятое решение

Выбранный вариант: **карта доступа R/RW (модуль III) с diff «разрешённое против
наблюдаемого»**. Для каждого ребра «инициатор → ресурс» продукт классифицирует чтение/запись,
фиксирует источник сигнала и уверенность и сопоставляет (diff) объявленные гранты с
наблюдаемым использованием, чтобы выявить **отклонение от наименьших привилегий
(least-privilege drift)**: неожиданные доступы, неиспользуемые гранты и рёбра,
ожидающие сверки (reconciliation-pending).

### Последствия

- **Хорошо:** отличительный, значимый для безопасности артефакт, на котором строится
  governance платформы, наряду с другими модулями, — а не функция в изоляции.
- **Плохо / компромиссы:** зависит от идентичности на уровне отдельного агента для
  твёрдой атрибуции (общая сервисная учётная запись схлопывается до *приблизительной*
  уверенности); покрытие **разделено на уровни (tiered)** по хранилищу; нужно честно
  отмечать `unknown` и `approximate`, а не фабриковать определённость.
- **Нейтрально:** карта доступа — это *представление (view)* поверх общей модели данных
  (см. ADR-0005), а не отдельная схема.

## Почему альтернативы были отклонены

- **Только наблюдаемое / только разрешённое** — каждое из них лишь половина картины;
  ценность именно в *diff*.
- **Просмотр сессий** — превращён в ширпотреб (вендоры поставляют «agent view»); не
  является устойчивым рвом (moat).
