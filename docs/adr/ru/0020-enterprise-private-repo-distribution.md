# ADR-0020: Распространение enterprise-редакции из отдельного закрытого репозитория

- **Status:** accepted
- **Date:** 2026-06
- **Deciders:** Fran Olivares
- **References:** ADR-0010 (license is attestation-only), ADR-0011 (license boundary),
  `LICENSING.md`

## Контекст и постановка проблемы

Модель лицензирования построена по принципу открытого ядра: AGPL-компоненты core/modules/web
образуют полную community-редакцию, SDK/connectors лицензируются под Apache-2.0, а ветка
`enterprise/` содержит дополнительный коммерческий код, собираемый только с `-tags enterprise`
(ADR-0011). Однако до настоящего момента исходный код `enterprise/` **поставлялся в публичном
репозитории**. Поскольку активационным барьером служит build tag (а не лицензия, которая согласно
ADR-0010 используется только для аттестации) и лицензия никогда не ограничивает runtime, любой мог
выполнить `git clone && go build -tags enterprise` и бесплатно получить полный коммерческий бинарный
файл. Коммерческий барьер целиком держался на юридической лицензии — системе чести поверх видимого,
свободно компилируемого кода.

## Движущие факторы решения

- Сделать ограничение через build tag **реальным**, а не декоративным: коммерческий бинарный файл
  нельзя собирать кому угодно только из публичного кода.
- Сохранить AGPL community-бинарник **побитно неизменным** — без rug-pull и без удаления уже открытых
  возможностей.
- Без изменений сохранить границу лицензий по каталогам (ADR-0011) и аттестационную лицензию
  (ADR-0010).

## Рассмотренные варианты

- **Оставить `enterprise/` в публичном репозитории** (модель GitLab с `ee/` в одном репозитории,
  source-available). Честно, но барьер остается системой чести поверх видимого и свободно
  компилируемого кода.
- **Перенести `enterprise/` в отдельный закрытый репозиторий** (модель Grafana: публичный OSS-код +
  загружаемый enterprise-бинарник, собранный из закрытого кода).

## Результат решения

Выбран вариант: **перенести `enterprise/` в отдельный закрытый репозиторий**. Публичный репозиторий
больше не содержит дерево `enterprise/`, wiring `cmd/olivares` с `//go:build enterprise` и инструменты,
собирающие с `-tags enterprise`. Коммерческий бинарник собирается в закрытом репозитории: коммерческое
дерево и wiring накладываются на закреплённый checkout публичного дерева (публичное дерево является
submodule; wiring накладывается на `package main` в `cmd/olivares`, чего нельзя добиться одним лишь
выбором модулей в `go.work`).

Меняется только **распространение**, не лицензирование:

- **ADR-0011 (граница лицензий) остаётся без изменений:** `enterprise/` по-прежнему имеет
  `LicenseRef-Olivares-Commercial`; граница AGPL/Apache сохраняется.
- **ADR-0010 (аттестационная лицензия) остаётся без изменений:** открытый бинарник по-прежнему не
  читает лицензию для включения или отключения чего-либо. Лицензия становится *материально* значимой
  только потому, что код, читающий аттестованное утверждение (add-on entitlements), теперь закрыт, а не
  потому, что лицензия начала ограничивать runtime.

### Последствия

- `git clone` публичного репозитория + `go build -tags enterprise` больше не создают коммерческий
  бинарник: необходимый код закрыт. Ограничение теперь реально.
- Стандартный AGPL-бинарник не изменён — он и прежде не линковал `enterprise/`.
- Проверка open≡enterprise schema parity, которой нужны обе редакции, переносится в закрытый
  репозиторий — единственное дерево, способное собрать обе.
- Цена решения — два репозитория и небольшой шаг сборки overlay; публичный release artifact не
  затронут (он уже собирался с `-tags release`, а не с `-tags enterprise`).

## Поправка (2026-07-28) — упомянутое выше право на места исчезло

Решение о распространении остаётся в силе: `enterprise/` находится в закрытом
репозитории, а ограничение через build tag реально. Больше не действует *пример*,
использованный в разделе «Последствия»: «исходный код, читающий аттестованное утверждение
(право на места)». Решение B10 (2026-07-27) отменило пользовательский лимит, поэтому
права на места больше нет и ни одна сборка не читает лицензию, чтобы ограничивать
пользователей; оставшиеся аттестованные утверждения читаются только для предоставления
прав на аддитивные add-on'ы. Исходное предложение оставлено без изменений, поскольку оно
фиксирует то, что было верно на момент принятия этого ADR. Текущее решение:
коммерческий канон цен (ведётся приватно) (`self_hosted.users: unlimited`) и
`LICENSING.md`
