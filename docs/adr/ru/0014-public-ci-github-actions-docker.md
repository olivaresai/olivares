# ADR-0014: Публичный релиз и CI на GitHub Actions + Docker

- **Status:** accepted
- **Дата:** 2026-06-04
- **Принявшие решение:** Fran Olivares (стартовое решение)
- **Ссылки:** стартовые решения дорожной карты (Release/CI)

## Контекст и постановка проблемы

Разработка ведётся в приватном репозитории; публичной, проверяемой цепочке поставок
нужна широко доверяемая, прозрачная площадка CI/релизов (для бесключевых подписывающих
идентичностей, происхождения SLSA и публичного распространения артефактов).

## Факторы решения

- Публичная, проверяемая релизная идентичность (OIDC) и журнал прозрачности для подписи.
- Стандартное, широко доверяемое распространение контейнеров.
- Сохранять повседневную разработку приватной, пока релиз не будет курирован и опубликован.

## Рассмотренные варианты

- **GitHub Actions + Docker для всех публичных артефактов; приватный репозиторий разработки.**
- **Self-hosted CI и для публичных релизов тоже.**

## Итог решения

Выбранный вариант: **GitHub Actions + Docker для всего публичного, всегда**; **разработка
ведётся в приватном репозитории**. Идентичность OIDC GitHub Actions релизного workflow — это
то, что подтверждают бесключевые подписи и происхождение SLSA, а образы/чарты публикуются
в публичный OCI-реестр.

### Последствия

- **Хорошо:** подписи и происхождение увязываются с публичной, проверяемой идентичностью;
  стандартное распространение; разработка остаётся приватной до намеренной публикации.
- **Плохо / компромиссы:** публичный репозиторий — это курируемый экспорт приватного
  репозитория разработки, а не живое зеркало.
- **Нейтрально:** публикация публичного репозитория — это осознанное, контролируемое действие.

## Почему альтернативы были отклонены

- **Self-hosted CI для публичных релизов** — self-hosted подписывающую идентичность
  гораздо труднее проверить третьим сторонам, чем публичную идентичность OIDC GitHub Actions
  с журналом прозрачности.
