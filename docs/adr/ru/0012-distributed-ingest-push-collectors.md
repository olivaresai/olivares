# ADR-0012: Распределённый приём данных — коллекторы отправляют данные в ядро по gRPC + mTLS

- **Status:** accepted
- **Date:** 2026-06-04
- **Deciders:** Fran Olivares (boot decision CB-1)
- **References:** roadmap boot decisions (CB-1 → option C); runtime-ingestion contract

## Контекст и постановка проблемы

Для плоскости приёма данных требовалось решение по топологии. Коллекторы ведут наблюдение
на хостах заказчика; ядро выполняет агрегацию. Варианты варьировались от исключительно
внутрипроцессного до полностью распределённой модели push, с последствиями для изоляции,
сетевой границы доверия и упаковки.

## Факторы, определяющие решение

- Удерживать плоскость данных на инфраструктуре заказчика с защищённым пересечением сети.
- Сохранить единый бинарный файл для простого случая.
- Изолировать зависимости коллектора от ядра.

## Рассмотренные варианты

- **C — удалённый push:** коллектор запускает коннекторы-источники локально и
  **отправляет (push)** наблюдения в ядро по **gRPC + mTLS**, при этом у коллектора
  **отсутствует входящий слушатель**.
- **B — внепроцессный локальный:** коннекторы как локальные подпроцессы (AutoMTLS),
  субстрат одного узла.
- **A — внутрипроцессный:** источники, скомпонованные в бинарный файл (быстрый путь для
  собственных источников).

## Итоговое решение

Выбранный вариант: **C (удалённый push) как распределённая цель**, при этом B служит
субстратом одного узла, а A сохраняется как внутрипроцессный быстрый путь для собственных
источников. Все транспорты входят в v1; C **не** откладывается. Механизм размещается в
runtime; распределённая упаковка (DaemonSet/Helm) поставляется вместе с работой по цепочке
поставок.

### Последствия

- **Плюсы:** данные пересекают сетевую границу в защищённом виде (mTLS + bearer + authz);
  коллектор не открывает ни одного входящего порта; единый бинарный файл сохраняется.
- **Минусы / компромиссы:** больше движущихся частей для распределённого развёртывания.
- **Нейтрально:** вариант с единым бинарным файлом по умолчанию использует
  внутрипроцессный путь / путь локального подпроцесса.

## Почему альтернативы были отклонены

- Ни **A**, ни **B** по отдельности не покрывают масштабирование на множество хостов;
  они сохраняются соответственно как быстрый путь и как субстрат одного узла, а не как
  распределённый ответ.
