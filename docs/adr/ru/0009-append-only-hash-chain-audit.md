# ADR-0009: Журнал аудита: только добавление, хеш-цепочка, подпись

- **Status:** accepted
- **Date:** 2026-06
- **Deciders:** Olivares AI
- **References:** API/authz/audit contract (§6, decision §13.4); threat model (ledger)

## Контекст и постановка проблемы

Журнал аудита (audit ledger) — один из самых чувствительных активов продукта: если его можно незаметно
изменить, продукт лжёт. Он должен делать подделку обнаружимой и поддерживать внешние,
проверяемые копии — оставаясь честным в отношении того, что целостность на хосте может и чего не может
гарантировать.

## Факторы, влияющие на решение

- Доказуемость подделки (tamper-evidence): переписывание истории должно быть обнаружимым.
- Возможность проверки вне хоста для комплаенса и реагирования на инциденты.
- Отсутствие новой подсистемы хранения для контрольных точек.

## Рассмотренные варианты

- **Только добавление + хеш-цепочка (hash-chain) + контрольные точки, подписанные Ed25519**, с экспортом во внешнюю
  копию WORM/SIEM.
- **Простая таблица аудита** с контролем на уровне приложения.

## Принятое решение

Выбранный вариант: журнал **только для добавления, с хеш-цепочкой (hash-chained)**; контрольная точка сама является подписанным
событием аудита (Ed25519, отсоединённая подпись), так что переписывание истории до контрольной точки
криптографически обнаружимо. Журнал экспортируется во внешние форматы SIEM/WORM (CEF,
LEEF, syslog, OTLP — полный экспортный запрос, готовый к отправке через POST, а
простая проекция LogRecord доступна как отдельный экспортный токен `otlp_log_record` — OCSF),
при этом каждая запись несёт поля цепочки, так что SIEM может
повторно проверить их офлайн; PII (персональные данные) никогда не экспортируются.

### Последствия

- **Хорошо:** доказуемость подделки без отдельной таблицы контрольных точек; повторная офлайн-проверка;
  экспорт, готовый для SIEM.
- **Плохо / компромиссы:** ключ подписи на диске не останавливает root хоста / суперпользователя
  БД — поэтому **внешний экспорт WORM/SIEM является реальным средством защиты от подделки**, и
  документация прямо это говорит.
- **Нейтрально:** на момент принятия этого решения экспорт был основан на вытягивании
  (pull-based); стык для автоматического push-форвардера существовал, но ещё не был
  реализован.

  > **Поправка о статусе, 2026-07-25.** Push-форвардер реализован и подключён:
  > `modules/siemforward` удовлетворяет `audit.Forwarder`, а `cmd/olivares/boot.go`
  > запускает журнальный насос для каждого арендатора при наличии подписки на событие
  > `audit.recorded`, доставляя каждую запечатанную запись не менее одного раза по
  > долговечному транспорту. `NopForwarder` применяется, когда пересылка не настроена.
  > Экспорт по pull остаётся доступным без изменений. Само решение не менялось.

  > **Поправка к статусу, 2026-07-28.** Утверждение выше «SIEM может повторно
  > проверить всё офлайн» на момент принятия решения относилось только к СВЯЗНОСТИ
  > цепочки и подписи контрольной точки: проекции не переносили обязательство по
  > метаданным события, поэтому собственный хеш записи нельзя было заново вычислить
  > из экспортированной строки. Теперь это возможно: каждый вход, потребляемый хешем
  > цепочки, переносится во всех диалектах, включая обязательство по метаданным; это
  > обязательство ОСЛЕПЛЯЕТСЯ отдельно для каждой записи, поэтому раскрытие прообраза
  > ничего не сообщает о скрытых за ним метаданных. Три утверждения остаются
  > различными, и предложение в этом ADR охватывает только первое: пересчёт прообраза,
  > НЕ подлинность (внешне доверенный ключ) и НЕ полноту (соседние записи и контрольная
  > точка).
  >
  > В запись решения входят два следствия. Оба правила хеширования метаданных теперь
  > действуют постоянно и различаются по сохранённому в строке ослепляющему значению:
  > append-only-журнал не может переопределить правило хеширования уже опечатанных
  > строк, не сделав законную историю неотличимой от подделанной. По той же причине
  > формат архива получил версию для переноса ослепляющего значения, а предыдущая
  > версия будет приниматься всегда: у артефакта, рассчитанного на чтение спустя годы,
  > нельзя отозвать версию. Само решение не изменилось.

## Почему альтернативы были отклонены

- **Простая таблица аудита** — не даёт криптографической доказуемости подделки; неприемлемо для
  продукта в области безопасности, целостность журнала которого — «это всё».
