# ADR-0015: 供应链 —— 签名发布、SBOM、SLSA 来源、OpenVEX、distroless

- **Status:** accepted
- **日期:** 2026-06
- **决策者:** Fran Olivares
- **参考资料:** 技术栈决策（T6/T7）；供应链与发布验证设计

## 背景与问题陈述

对于一个安全产品而言，未签名或不可验证的发布是不可接受的。买方需要验证*他们下载的内容*
—— 包括在完全离线、隔离网络（air-gapped）环境中 —— 并且需要知道每个制品的来源以及已知漏洞状态。

## 决策驱动因素

- 每个制品在线上与离线下的密码学可验证性。
- 来源（谁构建了它，来自什么源代码）以及一份软件物料清单（SBOM）。
- 一个最小化、按摘要钉定（pinned）的运行时镜像。

## 考虑的方案

- **cosign/sigstore 签名 + SBOM（syft）+ SLSA Build L3（SLSA v1.2）来源 + OpenVEX +
  按摘要钉定的 distroless 镜像**，并配备一条离线验证路径以及一个隔离网络捆绑包（air-gap bundle）。
- **仅校验和 / 未签名发布。**

## 决策结果

所选方案：**完整的供应链组合**。发布版本附带 cosign 签名、SPDX + CycloneDX SBOM、
SLSA Build L3 来源以及 OpenVEX 证明（attestation）；容器镜像采用 **distroless，按摘要钉定**。
一个验证脚本会检查整条链路，包括一种**完全离线**模式，并且一个**隔离网络捆绑包（air-gap bundle）**
会携带一个公钥，使得一个断网站点无需透明度日志即可验证一切。

### 后果

- **优点：** 每个制品都可验证，无论在线还是离线；来源与 SBOM 随每次发布一同提供；运行时镜像最小化且
  不可变（按摘要）。
- **缺点 / 权衡：** 需要维护更多的发布机制；隔离网络捆绑包要求将 SBOM/VEX/来源提供给打包器。
- **中性：** 部署始终按摘要进行，绝不按标签。

## 为何拒绝其他方案

- **仅校验和 / 未签名** —— 不提供来源、无离线信任根、也无漏洞声明；在一个安全产品中不可接受。

## 补充说明（2026-07-03）：SLSA v1.2 措辞与 Source 轨道评估

SLSA 措辞统一为 **SLSA Build L3（SLSA v1.2）**。在 SLSA v1.2 中，
Build 轨道最高为 L3，因此本 ADR 只声明 Build 轨道等级。

Source 轨道评估保持独立。Source L1–L3 需要保留源代码修订，并由源代码控制
系统提供来源证明；Source L3 还要求持续、可检测篡改的执行机制，例如 gittuf
或平台证明。

当前状态：分支保护已编写在 `scripts/apply-branch-protection.sh` 中，但源代码
来源证明尚未部署。

决策：不声明任何 Source 轨道等级；持续关注 Source 轨道，并在公开发布时重新评估。
