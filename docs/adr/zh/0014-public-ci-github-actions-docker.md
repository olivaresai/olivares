# ADR-0014: 在 GitHub Actions + Docker 上进行公开发布与 CI

- **Status:** accepted
- **日期:** 2026-06-04
- **决策者:** Fran Olivares（启动决策）
- **参考资料:** roadmap 启动决策（发布 / CI）

## 背景与问题陈述

开发工作在一个私有仓库中进行；而公开、可验证的供应链需要一个广泛受信任、透明的
CI / 发布平台（用于无密钥签名身份、SLSA 来源（provenance）以及公开制品分发）。

## 决策驱动因素

- 一个公开、可验证的发布身份（OIDC）以及用于签名的透明度日志（transparency log）。
- 标准、广泛受信任的容器分发方式。
- 在发布版本被精心整理并发布之前，保持日常开发的私密性。

## 考虑的方案

- **所有公开制品都使用 GitHub Actions + Docker；并使用一个私有开发仓库。**
- **公开发布也使用自托管 CI。**

## 决策结果

所选方案：**所有公开制品都始终使用 GitHub Actions + Docker**；**开发工作在一个私有仓库中进行**。
发布工作流的 GitHub Actions OIDC 身份正是无密钥签名和 SLSA 来源所证明的对象，镜像 / charts
则发布到公开的 OCI 镜像仓库。

### 后果

- **优点：** 签名与来源链接到一个公开、可验证的身份；标准化分发；开发在被有意发布之前保持私密。
- **缺点 / 权衡：** 公开仓库是私有开发仓库的一份精心整理的导出，而非实时镜像。
- **中性：** 发布公开仓库是一个有意为之、受门控的动作。

## 为何拒绝其他方案

- **为公开发布也使用自托管 CI** —— 相比带有透明度日志的公开 GitHub Actions OIDC 身份，
  自托管的签名身份对第三方而言要难验证得多。
