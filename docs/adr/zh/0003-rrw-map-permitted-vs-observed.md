# ADR-0003: 带有"已授权与已观测"差异对比的 R/RW 图是一项关键差异化能力

- **Status:** accepted
- **Date:** 2026-06-02
- **Deciders:** Fran Olivares
- **References:** product decisions register (P2); architecture (module III)

## 背景与待解决的问题

许多工具能*观测*智能体活动，许多工具也能*枚举*已授予的权限。但二者单独都无法回答
对治理而言真正重要的问题：**一个智能体被*允许*触及的范围，是否与它被*观测*到实际
触及的范围一致？** 产品需要一项可立得住、难以被商品化的能力来回答这一问题——它是
产品所提供的若干能力之一，而非产品的全部。

## 决策驱动因素

- 一项难以被商品化、且对安全/SOC 直接有用的能力。
- 由产品确实能够获取的信号（审计、遥测、内核）构建而成。
- 对保真度保持诚实，而非夸大其词。

## 考量过的选项

- 在读/写访问图之上的**"已授权与已观测"差异对比**（最小权限漂移）。
- **仅观测** —— 展示智能体做了什么。
- **仅授权** —— 展示已授予的权限。
- **会话查看** —— 展示实时的智能体会话。

## 决策结果

所选方案：**带有"已授权与已观测"差异对比的 R/RW 访问图（模块 III）**。对每一条
发起方→资源（origin→resource）边，产品都会分类其读/写性质、记录信号来源与置信度，
并将声明的授权与观测到的使用进行差异对比，以揭示**最小权限漂移**：意外的访问、未被
使用的授权，以及待对账（reconciliation-pending）的边。

### 影响

- **好处：** 一个独特、与安全高度相关的产物，平台的治理能力在其上构建，并与其余各
  模块并存——而非一项孤立的功能。
- **坏处/权衡：** 牢靠的归因依赖每个智能体的独立身份（共享的服务账户会退化为*近似*
  置信度）；覆盖范围按存储**分级**；它必须对 `unknown` 和 `approximate` 保持诚实，
  而不是捏造确定性。
- **中性：** 访问图是通用数据模型之上的一个*视图*（见 ADR-0005），而非一套独立的
  模式（schema）。

## 为何否决其他方案

- **仅观测/仅授权** —— 各自只是图景的一半；价值在于*差异对比*。
- **会话查看** —— 已被商品化（各家厂商都在交付"智能体视图"）；并非可持续的护城河。
