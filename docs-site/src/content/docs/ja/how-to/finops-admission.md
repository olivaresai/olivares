課金対象の処理は、実行前に見積もり支出を**予約**し、**単一のハンドル**を受け取り
ます。処理が実行されたら、呼び出し元はそのハンドルで計測したコストを**確定**
(commit) します。実行されなかった場合は保留を**解放** (release) します。エンジン
自身のゲート (推論プロキシ、セッション起動、スケジュールジョブ) はこれを自ら行い
ます。このページは、ルートを呼び出すコネクタと、結果を読む運用者向けです。

## 予約

```bash
olivares finops admission reserve --data @reserve.json -o json
```

```json
{
  "scope": "model_gateway",
  "idempotency_key": "gateway/req-7f3a",
  "estimate_micro_usd": 2000000,
  "actor_ref": "alice",
  "dims": { "provider_ref": "anthropic", "model_ref": "claude-sonnet-4" }
}
```

見積もりは、リクエストを対象とするすべての適用予算に対して保留され、
`actor_ref` を指定した場合はそのアクターの支出上限に対しても保留されます。応答は
単一のハンドルを返します。

```json
{
  "allowed": true,
  "handle": "0192f6c4-7d2e-7a31-9b7c-4d6f1e2a3b4c",
  "estimate_micro_usd": 2000000
}
```

見積もりがゼロの場合は何も保留せず、ハンドルも返しません。すでに上限を超えた
上限設定は、それでも拒否します。

| ステータス | 意味 |
|---|---|
| 200 | 許可。何も保留しなかった場合 `handle` は空です。`"unreachable": "allow"` の場合、確立できなかったアドミッションは保留なしで許可され、理由 `admission could not be established; admitted without a hold (unreachable=allow)` が付きます。 |
| 402 | ブロックの判定: `action=block` の予算または支出上限に余裕がない (シート単位の支出上限が拒否した場合 `spend_limit` は true)、予算の集合が大きすぎて評価できない、またはテナントが試行ライフサイクルのアクティベーション境界の下にあるか、その状態を読み取れない。理由がどれかを示します。 |
| 429 | `action=throttle` の予算に余裕がありません。 |
| 503 | アドミッションを確立できませんでした: 予算ストアを読み取れない、キーが再試行を超えて使用中のまま (別の呼び出し元の進行中のクレーム、または以前のビルドが公開した保留の組で、残りの保留がまだ保留しているもの)、キーが以前のビルドの残したクレームを保持している、またはキーの未精算保留リストを復号できない。理由は `budget store unreachable (deny-closed)` です。 |
| 409 | 冪等性キーが別の内容で使われました。 |
| 500 | キーのアドミッション行が整合性チェックに失敗しました。行が修復されるまで、そのキーはどの方針でも拒否されます。 |
| 400 | ドキュメントを処理できません: 不明なスコープ、キーの欠落、負の見積もり、またはスキーマが公開していないフィールド。 |

上限による 402 または 429 は確定的です。新しい期間または上限の引き上げまで、同じ処理を再試行しないでください。アクティベーション境界による 402 は、試行ライフサイクルがテナントの台帳を管理している間続きます。402、429、503、500 の拒否は監査行 `finops.admission.denied` にもなります。

アドミッションを確立できない場合の既定の方針は**拒否**です。予約ドキュメントに `"unreachable": "allow"` を設定すると、そのようなリクエストを保留なしで許可します。応答は上記の理由付きの 200 で、エンジンログはテナント、スコープ、`posture=allow outcome=admitted`、失敗の分類を ERROR で記録し、ストア自身のメッセージは記録しません。不明な値は拒否です。

## 再試行のルール

- **予約。** 同じ冪等性キーと同じ内容のリクエストは、リプレイ期間内であれば最初の
  呼び出しが受け取ったハンドルで応答されます (`"replayed": true`)。期間は応答から
  5 分間、保留が確定された後は確定から 5 分間です。期間外、および何も保留しなかった
  呼び出しでは、リクエストは改めて評価されます。
- **確定。** 応答が不確かな場合は、同じハンドルと同じ金額で `commit` を必要なだけ
  繰り返してください。どの繰り返しも同じ行に行き着きます。確定後に別の金額を送ると
  **409** で拒否されます。最初に計測されたコストが有効です。
- **解放。** 何度でも繰り返せます。解放が確定を取り消すことはありません。

## 確定と解放

```bash
olivares finops admission commit --data '{"handle":"0192f6c4-7d2e-7a31-9b7c-4d6f1e2a3b4c","actual_micro_usd":1500000}'
olivares finops admission release --data '{"handle":"0192f6c4-7d2e-7a31-9b7c-4d6f1e2a3b4c"}'
```

上限が過少に数えないよう、確定の前に計測コストを取り込んでください。ドキュメントは
`handle` のみで保留を指定し、それ以外のフィールドは 400 で拒否されます。空のハンドル
は何も精算しません。

| ステータス | 意味 |
|---|---|
| 200 | 精算済み、または同じ内容ですでに精算済み。 |
| 409 | 確定後の別の金額。アドミッションがまだ進行中のクレームで、どの呼び出し元もそのハンドルを受け取っていない保留。または、その資金が試行ライフサイクルに移った保留 (`lifecycle_api_required`)。 |
| 500 | 保留を指すアドミッション行が整合性チェックに失敗しました。何も書き込まれていません。取り込んだコストはそのままにし、行の修復後に同じ呼び出しを再試行してください。 |
| 400 | 保留の識別子ではないハンドル、または負の金額。 |

`committed: true` と `released: true` は呼び出しが受け付けられたことを示し、行が変わったことは示しません。空のハンドルの確定は何も精算せず、確定済みの保留の解放は確定のまま残します。

## 遅延確定のルール

確定は処理が実行されたことを記録するため、どれほど遅れて届いても受け付けられます。
解放の後、保留の期限切れの後、別の呼び出しがキーを引き継いだ後でも同様です。保留の
行は計測された金額で確定になり、保留が終わった時点を保持します。解放済みまたは期限
切れの行は何も保留していないため、予算の上限は変わりません。期限切れの保留を遅れて
確定すると、次の照合で `expired_unsettled` が減ります。

## 以前のアドミッションビルドが残した保留

以前のアドミッションビルドを実行したデータベースには、そのビルドが書いた行が残って
いることがあります。そのビルドが 2 つの保留で許可したキーは、どちらの保留でも精算
でき、両方が一緒に精算されます。そのビルドが進行中のまま残したクレームは、運用者が
宣言する停止時刻の下でのみ取り消されます。

```bash
OLIVARES_FINOPS_ADMISSION_LEGACY_WRITERS_STOPPED_AT=2026-09-20T09:00:00Z
```

以前のビルドのすべての書き込み側が停止した時刻を、`Z` で終わる UTC の RFC 3339
形式で設定します。起動時に一度だけ読み取られます。リカバリがそのようなクレームを
取り消すのは、その時刻から 5 分が経過した後で、かつそれらの書き込み側が残したどの
行もそれより後の日付を持たない間に限られます。空 (既定値) の場合は何も取り消し
ません。そのような時刻でないテキストも何も取り消さず、起動時にエラーを 1 件記録
します。レポートは状態を `legacy_stop` に示します: `absent`、`invalid`、`future`、
`contradicted`、`waiting`、`usable`。

## 照合

エンジンは、アクティブなすべてのテナントについて、リカバリを毎分、照合ジョブを
5 分ごとに実行します。

```bash
olivares finops admission reconciliation -o json
olivares finops admission reconcile -o json
```

`reconciliation` は予算の読み取り権限で読み取るだけで、リカバリ、掃除、報告は一切
行いません。`reconcile` は予算の書き込み権限で実行するジョブで、リカバリを実行し、
未精算のまま期限切れになった保留を掃除し、`drift` が true のときに種別
`finops_reservation_drift` の検出事項を記録します。コンソールは同じレポートを予算の
横に表示します。

| フィールド | 意味 |
|---|---|
| `active`、`committed`、`released` | 各状態の台帳行 |
| `expired_unsettled` | 誰も精算しなかった行。TTL が余裕を戻しました |
| `active_lapsed` | 期限を過ぎ、ジョブがまだ掃除していない行 |
| `idempotency_orphans` | ハンドルに台帳行がない予約済みアドミッション行 |
| `owed_remaining` | 進行中のクレームまたは公開済みの行がまだ負っている保留 |
| `legacy_pending`、`legacy_owes_release` | 以前のビルドが残したクレームと解放 |
| `unresolved` | 結果がまだ確定していないリカバリの書き込み。次のパスで改めて判断します |
| `undecodable` | 未精算保留リストを復号できないアドミッション行 |
| `frontier_blocked` | アクティベーション境界の下でリカバリが精算も破棄もできない保留 |
| `corrupt` | 整合性チェックに失敗したアドミッション行。数えるだけで書き込みません |
| `drift` | `expired_unsettled`、`active_lapsed`、`idempotency_orphans`、`unresolved`、`undecodable`、`corrupt` のいずれかがゼロでないとき true |

`unresolved` と `frontier_blocked` は `reconcile` のリカバリパスだけが数え、`reconciliation` では 0 と報告されます。

`owed_remaining` から `corrupt` までのカウンタがすべてゼロのとき、そのテナントで
リカバリがすべきことは残っていません。`corrupt` の行は、そのテナントのストアの
整合性障害として扱い、直近のバックアップと比較してください。その行が指す保留は TTL
で期限切れになり、行が修復されるまで精算されません。

## スコープ

| スコープ | 呼び出し元 |
|---|---|
| `model_gateway` | 推論プロキシとモデルルーティング: 呼び出し前に予約し、その後に確定または解放 |
| `session_launch` | 運用セッションの起動と音声のオープン |
| `scheduled_job` | オーケストレーションの起動、評価の判定、MCP タスク |
