---
title: "Olivares AI を使い始めて最初の 1 時間"
description: >-
  Olivares AI をインストールし、AI ツールでサインインするかプロバイダーを接続し、
  プロジェクトフォルダーで会話を始め、操作を 1 つ承認して、停止と再開を行います。
---

必要なものは、Docker Compose、ツールに作業させたいプロジェクトフォルダー、そして
ツールのサブスクリプション、プロバイダーの API キー、ローカルモデルのいずれかです。

## 1. インストールしてコンソールを開く

[README のインストール手順](https://github.com/olivaresai/olivares#install) に従ってください。
リリースイメージを明示的に選び、ホスト上のプロジェクトを `/project` にマウントし、
コンソールのアドレスと、置き換え用のワンタイムセットアップトークンを表示します。
Docker ホストに該当する場合は、README の AppArmor の手順を使ってください。

表示されたアドレスを開きます。最初のインストールは自己署名証明書を使うため、ブラウザーの
警告を受け入れる前に、開いているのが自分のサーバーであることを確認してください。セットアップ
トークン、メールアドレス、パスワードを入力して、最初の管理者を作成します。トークンとパスワードは
秘密にしてください。コンソールはあなたをサインインさせ、セットアップウィザードを開きます。

コンテナはサーバー上でツールを実行します。お使いのノートパソコンでサインインしたツールは
別のインストールであり、そのログインはコンテナにコピーされません。

## 2. ツールとそのログインを選ぶ

ウィザードを使うか、**AI ツール**（`/agent-tools`）を開きます。各ツールに、インストール済みか、
サインイン済みかが表示されます。インストールされていない場合は、インストールを確認して承認してください。
ツールのサインインコントロールを使い、ツール自身のログインフローを完了します。Claude Code または
Codex の場合は、Claude または ChatGPT のアカウントでのサインインを承認してください。

ネイティブインストールでは、既定のインスタンスはエンジンを実行しているユーザーのログインを使います。
Olivares を通じて行ったログインは、別のインスタンスとして残ります。ツールは、公開しているアカウント、
プラン、モデル、使用量の期間を報告します。利用できない値は残高がゼロであることを意味しません。
更新に失敗した場合は、最後のスナップショットが古いものとして表示され、失敗したコマンドが示されます。

代わりに API キーを使う場合は、**ツール** を開き、**API キー** の下にプロバイダーを追加して接続を
テストします。ローカルモデルの場合は、エンジンから到達できる Ollama のエンドポイントを追加します。
API キーは不要です。[プロバイダーを追加する](/ja/how-to/add-a-provider/) を参照してください。
Codex のようにモデルを必要とするツールでは、プロバイダーに保存済みの既定値がない場合、接続テストが
返したモデルを選択します。Claude Code はネイティブの既定モデルを使えます。

## 3. プロジェクトで会話を始める

1. **セッション**（`/sessions`）を開き、**新しいセッション** を選びます。
2. 準備ができたツールを選びます。フォームはフォルダーを表示し、そのフォルダーを自動で入力します。
   独自のフォルダーにあるセッションとして使う場合はそのままにします。または **フォルダーを変更** を選び、
   `/project` と入力して、README のインストールでマウントされたホストのフォルダーを使います。
3. **最初のメッセージ** を空のままにして **開始** を押します。会話が開いた後に、メッセージを入力できます。
   プロファイルとホームパスはエンジンが入力します。この最初のセッションのためにそれらを登録する必要はありません。

コンテナのユーザー（UID 65532）は、ホストのプロジェクトへの書き込み権限が必要です。権限については
[プロジェクトフォルダーの手順](https://github.com/olivaresai/olivares/blob/main/deploy/compose/README.md#work-on-a-host-project-folder)
を参照してください。セッションはマウントされたフォルダーの内容を変更できます。ホームディレクトリ全体ではなく、
プロジェクトのディレクトリを使ってください。

ツールにプロジェクトを説明させてください。返答は会話で読みます。**開始** を進められない場合は、
フォームが不足しているものを示します。その指示に従って **ツール** で対処してから、セッションに戻ってください。

## 4. 操作を承認する

承認を試すには、セッションを開始するときに **その他のオプション → 操作ごとに確認** を選びます。
プロジェクト内で無害なコマンドを実行するようツールに頼んでください。権限を要求してきたら、**ルール** を開きます。
あなたの対応を待っているリクエストは、オレンジ色で示され、キューの横に開いて表示されます。そこには、
コマンド、影響範囲、要求したルールが含まれます。**今回だけ承認**（`A` キーを押す）を選ぶか、
**拒否**（`D` キーを押す）を選んでメモを追加します。会話に戻って結果を読んでください。組織のポリシーにより、
セッションの起動前に承認が必要な場合もあります。その場合は、承認者が先にそのリクエストを受け入れる必要があります。

## 5. 停止して再開する

セッションで **停止** を選び、確認を求められたら確定します。ツールのプロセスは終了しますが、会話は残ります。
同じセッションで **再開** を選び、別のメッセージを送ってください。再開では、選択済みのプロファイル、
アカウント、フォルダーを保持し、それらがまだ使えるかを確認します。

継続的な運用、CLI、任意のプロファイル設定については、
[プロバイダーセッションを運用する](/ja/how-to/operate-provider-sessions/) を参照してください。

## ネイティブの起動メッセージ

他のインストール方法には、それぞれ別の検証上の制限があります。
[インストール](https://github.com/olivaresai/olivares/blob/main/INSTALL.md#installation-qualification)
を参照してください。ネイティブのクイックスタートは、コンソールのアドレスと、そのセットアップ状態に対する
次の手順を表示します。新規、再訪、セットアップ保留中のメッセージは次のとおりです。

```text
Next: Open the console; it guides setup, sign-in and your first session.
Next: Open the console and sign in to continue your work.
Next: Open the console to finish setup with the one-time token issued earlier.
```

ホスト全体の推論資格情報が設定されていない場合、エンジンの起動ログに次の行が含まれます。

```text
session runtime: no inference credential source configured; stream-json launches are deny-closed
```

これは、プロバイダーに紐づかずに managed injection を使う Claude プロファイルを制限します。紐づいた
プロバイダーキーやツールの認可済みログインは、別の資格情報ソースです。
[プロバイダーセッションを運用する](/ja/how-to/operate-provider-sessions/#接続方法を選ぶ) を参照してください。
