---
title: "管理された Git 公開"
description: "承認済みの Git ホスト設定と現在の権限に基づき、コミットの push、プルリクエストの作成とマージを行い、結果を記録します。"
---

gitpublish モジュールは、GitHub、GitLab、およびプレーンな git リモート（プッシュのみ）への管理された公開を提供します。Community に含まれます。

各操作には、承認済みの公開先、リポジトリと認証情報の設定、および現在の認可が必要です。必要な設定、Git 実行ファイル、または認可がなければ、公開は拒否されます。モジュールの登録だけでリポジトリが公開可能になるわけではありません。

API 名前空間は `/v1/m/gitpublish` です。公開先、push・プルリクエスト・マージの操作意図、照合、観測結果を扱います。

公開先の読み取り（`GET /targets` と `GET /targets/{id}`）には、承認済みの認証情報の設定から解決される読み取り専用の `host`（`github`、`gitlab`、`git`）が含まれます。コンソールがプルリクエストとマージを提供するのは GitHub と GitLab のみで、セッションの push の後に提示されるドラフトのプルリクエストも同様です。設定がすでに承認されていない場合、または古いエンジンが host を返さない場合、コンソールは push のみを提供します。エンジンはすべての操作について、必要な設定と認可を引き続き確認します。設定の参照に失敗した場合は、利用不可の応答を返します。

push ではセッション実行 (`session_run`) を指定できます。その場合 Olivares は公開の前に、その実行のフォルダーからコミットをサーバーリポジトリへ取得します。使うのはローカルのファイルプロトコルだけです。実行は公開先と同じワークスペースに属している必要があり、リクエストがパスを指定することはありません。

リモートの結果が不明な場合、再試行は許可されません。要求、観測結果、確認応答は別々に記録されます。送信済みのリモート操作は、その後のローカルな権限取り消しと競合する場合があります。
