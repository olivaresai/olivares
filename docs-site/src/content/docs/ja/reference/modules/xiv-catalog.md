モジュール XIV は組織の**内部カタログ** — 全社で**再利用が承認された**エージェント、MCP
サーバー、スキル、テンプレート、モデル、サードパーティコネクターの、キュレーションされ
ガバナンスされたレジストリです。estate が場当たり的なコピーではなく、精査されバージョン管理された
ケイパビリティに標準化できるよう、そして「承認済み」が wiki の中の言葉ではなく検証可能な何かを
意味するよう、存在します。Intelligence レイヤーに位置し、**作用サーフェスを持ちません**:
キュレーションし記録する一方で、プロビジョニングは別の場所で起こります。

## それは何か

カタログは**レジストリ**であって、ドキュメントストアではありません。**エントリー**は、再利用可能な
ケイパビリティの、キュレーションされバージョン管理された一つの定義であり、`agent`、`mcp`、
`skill`、`template`、`model`、`connector` のいずれかの種別を持ちます。各 `(kind, slug, version)`
は**それ自身が不変のアーティファクト**です — 新しいバージョンの公開は新しいエントリーを作成し、
承認と署名は**バージョンごとに**行われます。エントリーは固定されたライフサイクルを進みます:

`draft → pending → approved → deprecated`

**draft** のみが可変です; **承認はそれを凍結します**。エントリーのスペックはオペレーターが作成した
*定義* — トランスポート、モデル、プロンプトの参照、スコープ、そしてシークレットへの**参照** — で
あって、決して資格情報の値ではありません。作成／承認パスはインライン資格情報を運ぶスペックを拒否
するため、このモジュールは定義、参照、ガバナンスメタデータを格納し、シークレットやペイロードを
決して格納しません。

## バージョン管理、凍結、署名

承認こそが「承認済み」を検証可能にする場所です:

- **コンテンツハッシュ。** 承認時、エントリーは、その正規かつ決定論的にシリアライズされた前像に
  対する **SHA-256 コンテンツハッシュ**でピン留めされます。オペレーターが作成したすべての
  フィールドがカバーされるため、承認済みエントリーのその後のいかなる変更も**検知可能**です —
  署名がなくても改竄検知可能です。
- **台帳証明。** 承認は追記専用でハッシュチェーン化された監査台帳に記録され、それを承認した
  **実際のプリンシパル**に帰属されます。
- **Ed25519 署名。** カタログ署名鍵がプロビジョニングされている場合、承認はコンテンツハッシュに
  対する**デタッチド Ed25519 署名**も生成し、公開鍵と短いフィンガープリントを伴います —
  「承認済み = 検証可能」。署名鍵はエンジンのフェイルクローズドな鍵シームの下、ブート時にロードまたは
  ミントされ、監査台帳鍵とは**独立しています**; このモジュールは自身のカタログ鍵を所有し、
  エンジンの内部監査署名者に到達することは決してなく、トラスト境界をクリーンに保ちます。

検証はハッシュを再計算し、ノードに鍵が設定されている場合は署名を**トラストアンカー**として扱います:
剥がされた署名（ダウングレード）や他の鍵で作られた署名（差し替え）は **not verified** として報告
されます。`GET …/pubkey` は署名が有効かどうかを報告します; エントリーごとの `verified` /
`signed` / `signed_by` の状態は、エントリールートと検証ルートによって返されます。

## 検証済みサードパーティコネクター

`connector` エントリーは、**リリースされたサードパーティコネクタープラグイン** — ビルドされた
バイナリまたは OCI アーティファクト — をキュレーションします。そのスペックは、キュレーション対象を
記録します: アーティファクトの `sha256`（`artifact_digest`）、リリース／OCI 参照、パブリッシャー、
コネクターのディスクリプター名。エントリーは外部コネクターエコシステムのテナント向け**認証記録**
です: 「承認済み」を、単に「誰かが承認をクリックした」ではなく「そのサプライチェーン証明が
検証された」を意味させることができます。

このフローは MCP エントリーのアドミッションペアを反映し、独自のポリシーと判定の記録を持ちます
（エビデンスは種別ごとにカウントされるため、コネクターの判定が MCP の判定とテーブルを共有することは
決してありません）:

- `GET`/`PUT …/connector-admission/policy` — テナントごとのトラストルート:
  `require_signed`、オプションの `require_subject_digest`、Sigstore のアイデンティティ／発行者の
  ピン、ベアな公開鍵、CA ルート、そして in-toto の**プレディケート許可リスト**（デフォルトは
  SLSA provenance v1/v0.2 と SPDX/CycloneDX の SBOM — コネクターはモデルウェイトではなくビルド
  されたアーティファクトであるため、provenance と SBOM の形）。ポリシーがなければ**観測モード** —
  テナントがオプトインするまで何もゲートされず、ポリシーエンドポイントは誠実にそう述べます。
- `POST …/entries/{id}/admit` — エントリー種別（`mcp` または `connector`）でディスパッチされる
  一つの共有ルート: オペレーターが供給した Sigstore 証明バンドルを検証し、エントリーごとに一つの
  **claim 対 verified の判定**を記録します。リクエストが `expected_digest` をピン留めしない場合、
  バインディングは**エントリーの `spec.artifact_digest` からデフォルト化されます** — エントリーは
  自身がキュレーションするアーティファクトを名指すため、明示的にオーバーライドされない限り、
  アドミッションはそのアーティファクトにバインドされます。不正な形式のバンドルは `400` です;
  整形式だが検証に失敗するバンドルはエラーではなく、**記録された否定判定**です。
- `GET …/connector-admissions` — 記録された判定。エントリー（`entry_ref`）でフィルタ可能で、
  検証済み判定に限定可能（`verified=true`）。
- **デナイクローズドな承認ゲート。** `require_signed` がオンのとき、コネクターエントリーは、
  **エントリーが現在キュレーションしているダイジェスト**（`spec.artifact_digest`）に**バインド
  された**検証済みの provenance/SBOM アドミッション判定があるときにのみ承認（したがって*検証済み*
  コネクターとして掲載）できます; `require_subject_digest` がオンのとき、そのアーティファクト
  バインディング自体が確認されなければなりません。アドミッション後にキュレーション対象のダイジェストを
  編集するとゲートは無効化されます — 新しいアーティファクトに対する再アドミッションが必要です。

:::caution[誠実な限界]
カタログは**認証する**のであって、実行しません: コネクタープラグインが実際に*実行*してよいかを
決定するホスト側のゲートは、ここではなく control plane に存在します。証明バンドルはオペレーターが
供給します（`cosign download attestation` / `gh attestation download`）— OCI リファラーから
それらを取得することは外部のステップであり、Rekor 透明性ログの**包含**はネイティブに検証されません
（判定はその材料の存在を記録し、何がチェックされたかを正確に述べます）。
:::

## ガバナンス下のセルフサービス・インスタンス化

**インスタンス**は、**承認済み**エントリーをインスタンス化するセルフサービスのリクエストです —
承認済みエントリーのみがインスタンス化できます。このモジュールはリクエスト、その**プロベナンス**
（どのエントリーバージョンに由来するか）、そのターゲット、そのガバナンスステータスを記録し、
健全なステートマシン（`requested → approved`/`rejected → active`）を強制します。誰が承認してよいかを
**決定せず**、プロビジョニングも行いません: 承認の**決定**はガバナンスに、実際のプロビジョニングは
デプロイメントに属します。承認、非推奨化、署名、インスタンス化は、実際のプリンシパルに対して
**特権的で、RBAC でゲートされ、自己監査される**アクションです。

:::caution[誠実な限界]
- **作用なし、プロビジョニングなし。** モジュール XIV は*リクエスト*を記録しガバナンスします;
  ケイパビリティを立ち上げることは決してありません。承認の決定はガバナンスのもの、配線はデプロイ
  メントのもの — そしてそこでのライブな `apply`/`retire` 自体がデナイクローズドなシームです
  （エグゼキューターがプロビジョニングされるまで `503`）。[誠実さと限界](/ja/start/honesty-and-limits/)
  を参照。
- **署名は本物だが鍵に依存する。** Ed25519 署名は実装されており、署名鍵はブート時にデフォルトオンで
  プロビジョニングされます。**鍵が設定されていない**（または無効な鍵の）ノードでは、承認済み
  エントリーは**ハッシュでピン留めされ台帳で証明されるが未署名**です — API は署名が存在すると
  示唆するのではなく、`signing_enabled`/`signed` を通じて誠実にそう述べます。
- **キュレーションであって、観測ではない。** カタログはイベントバスを購読も発行も**しません**;
  ライブな観測から導出されるのではなく、人々が API を通じて投入します。組織が*再利用のために承認した*
  ものを主張するのであって、現在実行されているものを主張するのではありません。
- **このモジュールは承認ポリシーを強制しない。** ステートマシンと RBAC の動詞ティアを強制します;
  *誰が*どの条件下で承認してよいかはガバナンスが決定します。
:::
