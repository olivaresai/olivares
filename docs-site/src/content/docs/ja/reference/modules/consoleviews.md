`consoleviews` モジュールは、コンソールに**保存済みビュー**を提供します。保存済み
ビューとは、コンソールが URL にエンコードするフィルター、時間範囲、スコープと
同じビュー状態に名前を付けたスナップショットです。これは**テナントごとに
サーバー側**へ保存されるため、たとえば*「過去 24 時間の失敗したアドミッション」*
という調査がブラウザーを閉じても残り、運用者が別の端末から利用でき、共有すれば
チーム全体がワンクリックで開けます。

## 保存するものと、決して保存しないもの

保存済みビューは**パラメーターだけ**です。ビューの URL 状態を保持するサイズ制限
付きの JSON オブジェクト（最大 4 KB）に、名前、任意の説明、所有プリンシパル、
`shared` フラグが加わります。このモジュールは、**クエリ結果、台帳の行、または
パラメーターが選択するデータを一切保存しません**。保存済みビューを読み込むと、
呼び出し元自身の権限で基礎となるクエリが再実行されます。コンソールは保存された
パラメーターを厳密にデータとして扱います。

## 所有権、共有、操作できる主体

- **作成/更新** — `consoleviews:view:write`（editor tier）を持つ任意のメンバー。
  ビューは作成したプリンシパルに属し、編集できるのは所有者だけです。
- **可視性** — 所有者は常に自分のビューを確認できます。`shared` とマークされた
  ビューは、`consoleviews:view:read`（viewer tier）を持つテナントの全メンバーに
  表示されます。閲覧権限のないビューへの応答は `403` ではなく常に `404` となり、
  その存在を漏らしません。
- **削除** — 所有者、またはテナントの **admin/owner ロール**が任意のビューを削除
  できます（退職したユーザーが残したビューを整理するための権限です）。
- **上限** — 所有者あたり 200 ビュー、テナントあたり 2,000 ビューです。上限に
  達すると明確なメッセージで拒否されます。`(feature, owner, name)` が自然キーで
  あり、同じ機能で同名のビューを保存すると `409` が返ります。

作成、更新、削除はすべて、実際のプリンシパルに帰属させてテナントの監査台帳に
記録されます。記録されるメタデータが識別するのはビュー（機能、名前、共有フラグ）
であり、そのパラメーターは決して記録されません。

## ルート

| メソッド | ルート | 権限 |
|---|---|---|
| `GET` | `/v1/m/consoleviews/views?feature_id=` | `consoleviews:view:read` |
| `GET` | `/v1/m/consoleviews/views/{id}` | `consoleviews:view:read` |
| `POST` | `/v1/m/consoleviews/views` | `consoleviews:view:write` |
| `PUT` | `/v1/m/consoleviews/views/{id}` | `consoleviews:view:write` |
| `DELETE` | `/v1/m/consoleviews/views/{id}` | `consoleviews:view:write` |

モジュールのルートは **beta** サーフェスの一部です。
[モジュールルートのリファレンス](/reference/api-beta/)を参照してください。

## 明示されている制限

- サーバーはビューの `feature_id` を slug として検証しますが、コンソールの機能
  リストを**固定しません**。コンソールレジストリが正であり、リリースごとに変わり
  ます。コンソールは、すでに存在しない機能の保存済みビューを無視します。
- 共有ビューが共有するのは結果ではなく**パラメーター**です。同じ保存済みビューを
  開いた 2 人の運用者でも、権限が異なれば表示されるデータが異なる場合があります。
  これは設計どおりであり、共有によってアクセス範囲が広がることはありません。
- 保存済みビューはコンソールの利便機能であり、証拠ではありません。ビュー自体は
  台帳のチェーン外にあり、証拠化されるのはライフサイクルイベントだけです。
- **ワークスペースに限定された**運用者は保存済みビューを読めますが、作成、編集、
  削除はできません。スコープ付きグラントエンジンは、限定されたプリンシパルによる
  コレクションレベルの書き込みをデニークローズドで禁止し、さらにテナント全体の
  管理者による削除オーバーライドからも限定された管理者を明示的に除外します。
- Postgres で複数の writer が同時に処理する場合、所有者単位およびテナント単位の
  上限はソフト上限です（わずかな超過は一定範囲に抑えられます）。同名ビューは常に
  ハードに拒否されます。
