Olivares AI は**オープンコア**です。**完全な製品**は GNU Affero General Public License のもとで公開されており、AGPL ビルドはガバナンスプラットフォーム全体そのものです。有償エディションへ誘導するために内部から機能を削ることは決してありません。その上に、`enterprise/` に小さな**加算的な**商用アドオン群が乗ります。これらは `-tags enterprise` を付けたときにのみビルドされ、公開バイナリには含まれません。商用ライセンスはコピーレフトに対する法的例外を提供します。`enterprise/` の機能は**個別のオプションのアドオン**としてライセンスされます。したがってオープンエディションと商用エディションは**同一ではありません**が、オープンに公開されたものが壁の向こうへ移されることは決してありません（コアに機能ペイウォールを設ける方式ではなく、GitLab の `ee/` モデルです）。

## ライセンスの境界

ライセンスはソースツリーに従います。すべてのファイルが SPDX ヘッダーを持ち、その境界は CI で強制されます（コネクタはエンジンを import してはなりません）。

| パス | ライセンス | 内容 |
|---|---|---|
| `core/` | **AGPL-3.0-only** | エンジン: 取り込み、イベントバス、データモデル、モジュールランタイム、API、認可、監査 |
| `modules/` | **AGPL-3.0-only** | 30 個のモジュール（インベントリ、R/RW マップ、FinOps、評価、ガードレール、…） |
| `web/` | **AGPL-3.0-only** | React 製 UI |
| `sdk/` | **Apache-2.0** | コネクタ／モジュールのインターフェース、gRPC 契約、共有型 |
| `connectors/` | **Apache-2.0** | コネクタ（Claude、OpenAI、pgAudit、eBPF、クラウド、Slack、SIEM、…） |
| `enterprise/` | **商用** | 加算的なアドオン。ビルドタグでゲートされ、公開バイナリには決して含まれません: マルチ IdP フェデレーション、コンテンツファイアウォール／DLP、フック強化、コンパイル済み脅威インテリジェンスカタログ、サーバーツールの egress、CyberArk Conjur、インシデントクローズループ（`LicenseRef-Olivares-Commercial`） |

いまご覧になっているドキュメントサイトも AGPL 製品の一部です。

## これがあなたにとって何を意味するか

- **製品のセルフホスト（AGPL）。** 完全な製品を AGPL のもとで実行、調査、改変、再頒布できます。AGPL のネットワーク利用条項が適用されます。改変版をネットワーク経由で他者に提供する場合は、その改変したソースを提供しなければなりません。社内でのセルフホストではこれが問題になることはまれです。Olivares AI の*上に*この義務なしで製品を構築したい場合は、まさにそのために商用ライセンスが用意されています。
- **コネクタの開発（Apache-2.0）。** SDK とコネクタは **Apache-2.0** であり、寛容かつコピーレフトなしです。コネクタを書いてプロプライエタリのまま保持し、好きなように出荷できます。これを安全にするアーキテクチャ上の境界は強制されています。Apache-2.0 のコネクタは **AGPL エンジンを決して import せず**、SDK のみに依存します。これによりコネクタのエコシステムはコピーレフトの摩擦から解放されます。
- **商用ライセンス。** AGPL の義務を回避する必要がある組織（たとえば製品をプロプライエタリな提供物に組み込む場合）は、商用ライセンスを取得できます。お問い合わせは **enterprise@olivares.ai** まで（価格はお問い合わせください）。上記の加算的な `enterprise/` アドオンは、それぞれオプションの権利として個別にライセンスされます。

## オープンとエンタープライズの境界

オープンバイナリはガバナンスプラットフォーム全体です。`enterprise/` 系列は**加算的**です。2 つの境界は特筆に値します。オープンビルドはそれらを偽装するのではなく、正直に応答するからです。

- **SSO** — シングル IdP ログイン（OIDC + SAML 2.0）はデフォルトバイナリで**オープン**です。実際のログインで、`-tags enterprise` は不要です。複数のアクティブな IdP（テナントごと／ドメインごと）、SSO 強制、マネージド SCIM は予約されたエンタープライズ系列です。2 つ目のアクティブな IdP を有効化しようとすると `multi_idp_requires_enterprise` が返ります。
- **ユーザーアカウント** — **どのエディションでも無制限**です。コミュニティビルドにユーザー上限はなく、エンタープライズビルドにもありません。ライセンスの状態（有効・期限切れ・不在）によってデプロイが運用できるアカウント数が制限されることはありません。2026-07-27 以前にあったアクティブ 3 アカウントの上限は完全に撤廃されました。シートのシームは互換性のための no-op としてコードに残っていますが、何も拒否しません。ライセンスが失効しても、アカウントが制限・無効化・削除されることはありません。

オープンとエンタープライズの全体像については [正直さと制限](/ja/start/honesty-and-limits/) を参照してください。

## ライセンスキーはオープン製品を決してゲートしない

これは重要かつ意図的な点です。オープン（AGPL）バイナリでは、ライセンス検証は**証明（attestation）のみ**です。エンジンは誰がライセンスを保持しているか、その状態は何かを記録しますが、ライセンスチェックによっていかなるリクエスト、いかなるモジュール、起動を**無効化、劣化、ブロックすることは決してありません**。また**オフライン**で動作し（Ed25519 署名、ライセンスサーバー不要）、だからこそオープン製品はエアギャップ環境（air-gapped）で動作します。ライセンスが表示されるのではなく*消費される*唯一の場所はクローズドなエンタープライズビルドであり、その用途は商用契約が対象とするアドオンの権限付与だけで、アドオンごとに評価されます。これは商用エディション内のローカルな判断であって、オープンバイナリ内のチェックではありません。ユーザー数が制限されることは決してありません。アカウントはどのエディションでも無制限です。したがってオープンビルドは本当に完全で、ライセンスによる上限はかかっていません。商用エディションで異なるのは加算的な `enterprise/` アドオンであって、同じバイナリの中でライセンスキーが機能をオン・オフすることではありません。

## なぜこのモデルなのか

コアを削るという選択肢は却下されました。オープンエディションは仕事全体をこなします。1 ノードで完結するガバナンスループ全体です。そのため上限を設ければより劣った製品になり、信頼を損ないます。すべてを寛容ライセンスにする方式（コアに MIT/Apache）は、商用的な足場を持たないままコアを譲り渡すことになります。ソース利用可能だが非 OSS のライセンス（BSL、SSPL など）は、拡張可能なコネクタエコシステムの全目的であるオープンソースの普及を殺してしまいます。そこでモデルは**オープンコア**です。それ自体で完全かつ信頼に足るコピーレフト製品、コネクタエコシステムを摩擦のないものに保つ寛容な SDK、そしてオープンビルドには決して含まれていなかった新しいコードからなる小さく**加算的**な商用系列、加えてクリーンな商用例外です。*セルフホストできる範囲を一切劣化させることなく*。

## コントリビューション

コントリビューションはプロジェクトのコントリビューション条件のもとで受け付けられます（リポジトリは DCO と CLA の両方、加えて商標ポリシーを同梱しています）。現在のプロセスについてはリポジトリの `CONTRIBUTING` ガイドを参照してください。
