リポジトリは `deploy/compose/` 配下に Compose スタックを同梱しています：堅牢化された
シングルノードデプロイ（組み込み SQLite、外部依存ゼロ）に加え、2つのオーバーレイ —
**Postgres マルチテナント**のオーバーライドと、**ディザスタリカバリ バックアップ**の
プロファイルです。このチュートリアルは、`up -d` からバックアップを備えた設定済みの
control plane までを案内します。

コンテナは、他のすべてのインストールと**同じ単一バイナリ**をラップします。異なるのは
パッケージングだけです。以下のコマンドはスタック自身のドキュメント化されたエントリ
ポイント（`deploy/compose/*.yml`）であり、それらが駆動する初回起動フローは、
[シングルノードチュートリアル](/tutorials/getting-started/single-node/)でバイナリに
対してエンドツーエンドで検証されたものと同じです。

<Aside type="caution" title="公開済みの v26.9.0 イメージを digest で固定する">
リリース **v26.9.0** は署名済みイメージを公開しました。インストール面の証人は
`26.9.0` の Docker Hub と GHCR を **published** と記録しています
（`docs/releases/v26.9.0-install-surfaces.json`）。同じ誠実さは
[Docker でデプロイする](/how-to/docker-deployment/) にあります。
`OLIVARES_IMAGE=docker.io/olivaresai/olivares@sha256:<digest>` を設定し、まず
[検証](/how-to/verify-a-release/)してください — タグではなく digest で。代わりに開発ツリーを
動かすには、堅牢化された distroless イメージをソースからビルドし、スタックをそれに向けます：

```bash
task image                                   # builds olivares:dev
echo 'OLIVARES_IMAGE=olivares:dev' >> deploy/compose/.env
```
</Aside>

## 1. シングルノードスタックを立ち上げる（SQLite）

<Steps>

1. 起動します：

   ```bash
   docker compose -f deploy/compose/docker-compose.yml up --wait --wait-timeout 120
   ```

   設計上、得られるもの：

   | プロパティ | 値 |
   |---|---|
   | ポート | `8443`（HTTPS：REST + web UI）、`8444`（gRPC） — **すべてのホストインターフェース**に公開。これはサーバーだからです。`.env` に `OLIVARES_BIND=127.0.0.1` を設定するとホストだけに制限できます |
   | データ | 名前付きボリューム `olivares-data` → `/var/lib/olivares`（SQLite ストア、audit 署名鍵、TLS 素材） |
   | 堅牢化 | `65532:65532` として実行、read-only root、全 capability をドロップ、`no-new-privileges`、tmpfs `/tmp` |
   | ヘルスチェック | 組み込みの `olivares readyz` を直接実行（shell、curl、wget は不要）。ローカル `/readyz` の HTTP 200 だけを正常とする |

2. エンジンに現在地を尋ね、ログからワンタイムのセットアップトークンを読み取ります：

   ```bash
   # where the console answers, and whether setup is still pending. The image is
   # distroless: `docker exec … bash` has nothing to run, this needs no shell.
   docker compose -f deploy/compose/docker-compose.yml exec olivares olivares first-boot

   # the one-time setup token, printed once at first boot
   docker compose -f deploy/compose/docker-compose.yml logs olivares \
     | sed -n '/FIRST-BOOT SETUP/,/========================/p'
   ```

3. 最初の管理者を作成し、ログインし、組織を作成します —
   [シングルノードチュートリアル](/tutorials/getting-started/single-node/#3-claim-the-one-time-setup-token)
   とまったく同じです（API は同じ。TLS 証明書は初回起動時に自己署名されるため、
   ブートストラップには `curl -k` を使います）：

   ```bash
   curl -ksf -X POST https://localhost:8443/v1/setup \
     -H 'Content-Type: application/json' \
     -d '{"token":"<olst_ token>","email":"you@example.com","password":"<strong-password>"}'
   ```

</Steps>

<Aside type="tip" title="トークンを逃した？">
再起動してもトークンは再印字されません（保存されるのはそのハッシュだけです）。管理者がまだ
存在しない間は、何も再起動せずに代替トークンを鋳造できます。稼働中のエンジンは即座にそれを
受け付け、以前のトークンは使えなくなります：

```bash
docker compose -f deploy/compose/docker-compose.yml exec olivares \
  olivares first-boot --new-token
```
</Aside>

<Aside type="tip" title="4 つのコマンドと、それぞれに `-f` が要る理由">
このスタックは自身の Compose プロジェクト名を持つため、エンジンのコンテナは `olivares`
（`compose-olivares-1` ではありません）、override のサービスは `olivares-postgres-1` と
`olivares-backup-1` になります。Compose は compose ファイルを**作業ディレクトリ**から探し、
このファイルは `deploy/compose/` にあります — したがってリポジトリのルートで単に
`docker compose ps` と打つと *"no configuration file provided"* と返ります。毎回 `-f` を渡すか、
`export COMPOSE_FILE=deploy/compose/docker-compose.yml` を一度実行してください。

```bash
docker compose -f deploy/compose/docker-compose.yml exec olivares olivares first-boot
docker compose -f deploy/compose/docker-compose.yml logs olivares
docker compose -f deploy/compose/docker-compose.yml ps
docker compose -f deploy/compose/docker-compose.yml down
```

`olivares quickstart` は**ローカルバイナリ**の経路であり、こちらではありません。ここではサーバーは
すでに動いており（コンテナのコマンドは `serve`）、`quickstart` はコンテナ内で 2 つ目のエンジンを
起動してしまいます。
</Aside>


## 2. ソースを配線する

ソースは `OLIVARES_SOURCES_CONFIG` で名指しされる1つのオペレーターファイルで宣言します
（[ソースを接続する](/how-to/connect-a-source/)）。コンテナの場合、そのファイルをマウントし、
小さなオーバーライドで変数を設定します：

```yaml
# deploy/compose/docker-compose.sources.yml (yours — not shipped)
services:
  olivares:
    environment:
      OLIVARES_SOURCES_CONFIG: /etc/olivares/sources.json
    volumes:
      - ./sources.json:/etc/olivares/sources.json:ro
```

```bash
docker compose -f deploy/compose/docker-compose.yml \
               -f deploy/compose/docker-compose.sources.yml up -d
docker compose -f deploy/compose/docker-compose.yml logs olivares | grep "ingest: wired source"
```

`sources.json` 内のパスは**コンテナ**のパスであることを忘れないでください — 例えば
pgAudit のログ末尾には、Postgres のログディレクトリもコンテナ内に read-only でマウント
する必要があります。

## 3. 暗号化された DR バックアップ（`backup` プロファイル）

スタックは、**暗号化され、ledger の連続性を損なわない**バンドル（`olivares dr backup`）を
生成し、14日より古いバンドルをプルーニングするワンショットのバックアップサービスを同梱します：

```bash
# Write your KEK passphrase once (keep it OUT of the repo / image):
printf 'a strong DR passphrase' > deploy/compose/dr-pass

docker compose -f deploy/compose/docker-compose.yml \
               -f deploy/compose/docker-compose.backup.yml \
               --profile backup run --rm backup
```

スケジュールされた RPO のために、そのコマンドをホストの cron でラップし、**`olivares-backups`
ボリュームをオフサイトにミラー**してください — 同一ホスト上のバックアップはディザスタ
リカバリではなく、パスフレーズはバンドルとは別に運ばれなければなりません（3-2-1）。リストア
ドリル（`olivares dr verify`）を含む完全な手順は、
[バックアップとリストア](/how-to/backup-and-restore/)にあります。

## 4. オプション：Postgres マルチテナントのオーバーライド

マルチテナントのトポロジーには、Postgres オーバーライドを重ねます。これは Postgres 16 を
立ち上げ、**最小権限の `olivares_app` ロール**（superuser なし、`BYPASSRLS` なし —
row-level security がテナントのバックストップであるため、エンジンは特権ロールに対しては起動を
*拒否*します）をプロビジョニングし、エンジンをそれに向けます：

```bash
cp deploy/compose/.env.example deploy/compose/.env
# set POSTGRES_SUPERUSER_PASSWORD and OLIVARES_DB_PASSWORD in .env

docker compose -f deploy/compose/docker-compose.yml \
               -f deploy/compose/docker-compose.postgres.yml up -d
```

<Aside type="caution" title="Compose の Postgres はデモトポロジー">
このオーバーライドは compose ネットワーク内で `sslmode=disable` で接続します —
評価には問題ありませんが、本番には**不適切**です。本番の Postgres デプロイは
`sslmode=verify-full` での TLS と DSN シークレットを使います — それが
[Kubernetes/Helm 経路](/tutorials/getting-started/kubernetes/)です。
</Aside>
