Live-ingest (`modules/liveingest`) — один из 30 подключённых модулей:
**внутрипроцессный производитель**, а не слот возможности. Он не входит в историческую
нумерованную карту I–XXIII. Он существует по одной архитектурной причине: внепроцессный
`SourceConnector` может передавать только запечатанную сумму наблюдения (ребро / стоимость /
находка) по своему gRPC-контракту, в котором нет RPC для событий и нет текстового поля — поэтому
он **не может опубликовать детективное событие**. Только внутрипроцессный модуль обладает
способностью публикации на шину, поэтому live-ingest — это половина «живого отвода»
(live-tap), испускающая те события для модулей, которые их уже потребляют.

## Что это такое

Коннектор телеметрии Claude управляющей плоскости работает вне процесса как встроенный
плагин; его поток `Gather` несёт только замороженный `oneof` `Observation`. Этот протокольный
контракт намеренно заморожен (проверяется на ломающие изменения; см.
[политику стабильности API](/ru/reference/api-stability/)) и не несёт ни выдержки, ни
текстовой поверхности. Live-ingest — это внутрипроцессный производитель, который поставляет
два события, которые коннектор структурно не может: `guardrail.observed` для
[модуля IX](/ru/reference/modules/ix-security/) и `voice.telemetry.observed` для модуля XVI.
Он не владеет ни сущностями, ни REST-поверхностью; это публикующий компонент на
[шину событий](/ru/reference/events/).

## Что он производит — `guardrail.observed`

Это недостающий производитель для цепочки детекторов безопасности, которая уже потребляет
[`guardrail.observed`](/ru/reference/events/). Он **deny-closed и подключается по желанию**:

- **По умолчанию (инспекция выключена).** Модуль ни на что не подписывается, ничего не
  публикует и видимо логирует свою пустую половину — никогда не молчаливый no-op.
- **При включённом opt-in оператора.** Он подписывается на `edge.observed` и для ребра, чей
  ресурс является разрешённой ссылкой на инструмент, выводит **ограниченную, уже
  маскированную** выдержку `tool_args` и публикует её как `ObservedText`, несущий только
  нечувствительные ссылочные поля. Выдержка — это *идентификатор* ресурса, который коннектор
  уже замаскировал у источника (санированный путь, host+path без query или учётных данных,
  имя Bash-программы с отброшенными аргументами, ссылка на MCP-инструмент). Live-ingest
  ограничивает её, а цепочка безопасности снова её зажимает — тройная защита. *Содержимое*
  аргумента **отбрасывается на коннекторе и никогда не достигает шины.**

Затем цепочка детекторов автоматически испускает находку на каждое обнаружение, на реальном
трафике.

## Что он производит — `voice.telemetry.observed`

Подключённый внутрипроцессный производитель только для метаданных голосовых/realtime-ходов из
allow-list — никогда не аудио и никогда не текст транскрипта. Полезная нагрузка — это
типизированное значение, которое по построению не может нести аудио, транскрипт или PII, а
потребитель отклоняет любой образец с ключом вне allow-list или с отсутствующей ссылкой на
сессию/агента. Поскольку в этой сборке нет голосового realtime-бэкенда, **его никто не
вызывает**: половина наблюдения честно бездействует и не фабрикует никакой телеметрии, пока
её не начнёт питать бэкенд.

:::caution[Честные ограничения]
- **Deny-closed по умолчанию.** `guardrail.observed` ничего не публикует, пока оператор явно
  не подключит его; пустая половина логируется, а не скрывается.
- **Покрытие обнаружения узкое, и об этом сказано прямо.** Поскольку внутри процесса доступны
  только уже маскированные *ссылки* на аргументы, реалистичные обнаружения на этой
  поверхности — это PII или секрет, встроенный в ссылку, и аномальные/чувствительные паттерны
  ресурсов. **Prompt-injection и jailbreak недостижимы** — им нужно *содержимое* аргумента,
  которое коннектор отбрасывает. Поверхности `input` / `output` / `tool_result` требуют
  внутрипроцессного источника контента, которого у этой сборки нет при внепроцессном
  транспорте и замороженном протоколе.
- **Голосовая телеметрия бездействует.** В этой сборке нет realtime-бэкенда, поэтому эта
  половина ничего не производит, а не выдумывает образцы.
- **Он никогда не перемещает сырой контент и никогда не расширяет захват коннектора.** Минимум
  данных — это свойство самого протокола передачи, а не настройка, наложенная сверху.
:::

## Связанное

- [Справочник по шине событий](/ru/reference/events/) — полезная нагрузка
  `guardrail.observed` / `ObservedText` (маскированная выдержка на JSON-fallback, а не
  запечатанная сумма) и `edge.observed`.
- [Модуль IX — безопасность, ограничители и аудит](/ru/reference/modules/ix-security/) —
  цепочка детекторов, потребляющая поток `guardrail.observed`, который публикует этот модуль.
- [Модуль XVI — голосовые и realtime-агенты](/ru/reference/modules/xvi-voice/) — потребитель
  (бездействующей) половины `voice.telemetry.observed`.
- [Модуль II — живая работа и сессии](/ru/reference/modules/ii-sessions/) — выводит
  собственные `goal` / `agent_ref` / `summary` напрямую из сигналов, которые он уже
  потребляет, а не через событие live-ingest.
- [Каталог модулей](/ru/reference/modules/overview/) — 30 модулей и честное разделение
  Govern/Observe против Actuate, которое подкрепляет этот внутрипроцессный производитель.
- [Обзор архитектуры](/ru/explanation/architecture/overview/) — где находятся
  внутрипроцессные модули и внепроцессные коннекторы.
- [Честность и ограничения](/ru/start/honesty-and-limits/) — почему пустые половины
  объявляются, а не подделываются.
