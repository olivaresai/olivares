Reporting (`modules/reporting`) имеет статус **LIVE**. Модуль объединяет данные
платформы о соответствии, аудите и FinOps в один профессиональный документ,
чтобы аудитор мог скачать доказательства, а не копировать JSON из нескольких API.

## Встроенные отчёты

Open-core-модуль предоставляет по запросу пять типов отчётов:

- `compliance-evidence` — состояние соответствия по фреймворкам, статусы контролей и доказательства.
- `audit-summary` — сводка событий аудита и проверка целостности ledger.
- `finops-report` — расходы на AI по моделям и провайдерам.
- `access-review` — пользователи и данные доступа для периодической проверки.
- `executive-summary` — краткая сводка по управлению, рискам, затратам и внедрению.

`GET /v1/m/reporting/reports` перечисляет типы и форматы. Отчёт создаётся через
`GET /v1/m/reporting/reports/{type}`; по умолчанию возвращается HTML, а
`?format=pdf` скачивает PDF. Для маршрутов требуется `reporting:report:read`.

## Open core и enterprise

HTML по запросу входит в open-core-бинарник. PDF по запросу доступен, когда в
системе есть Chromium-совместимый исполняемый файл. **Enterprise add-on:**
создание отчётов по расписанию закрыто build tag и не входит в community runtime.

## Чёткие границы

- Для PDF Chromium запускается в headless-режиме. Если в `PATH` нет `chromium`,
  `chromium-browser` или `google-chrome`/`chrome`, запрос PDF возвращает `501`; HTML
  остаётся доступным.
- Для compliance-evidence нужен источник данных о соответствии. Если он не
  подключён, документ явно сообщает «Data source not configured», а не
  выдумывает доказательства.
- Модуль рендерит документы из уже имеющихся в платформе данных. Он не заменяет
  audit ledger, оценку соответствия или авторитетный источник FinOps.
