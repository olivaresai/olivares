Оплачиваемое действие **резервирует** оценку расходов до запуска и получает
**один handle**. Когда действие выполнено, вызывающая сторона **подтверждает**
(commit) измеренную стоимость этим handle. Если оно не выполнялось, она
**освобождает** удержание. Собственные шлюзы движка (прокси инференса, запуск
сессий и плановые задания) делают это сами. Эта страница для коннектора, который
вызывает маршруты, и для оператора, который читает результат.

## Резервирование

```bash
olivares finops admission reserve --data @reserve.json -o json
```

```json
{
  "scope": "model_gateway",
  "idempotency_key": "gateway/req-7f3a",
  "estimate_micro_usd": 2000000,
  "actor_ref": "alice",
  "dims": { "provider_ref": "anthropic", "model_ref": "claude-sonnet-4" }
}
```

Оценка удерживается по каждому применяемому бюджету, охватывающему запрос, а при
заданном `actor_ref` также по лимитам расходов этого участника. Ответ несёт один
handle:

```json
{
  "allowed": true,
  "handle": "0192f6c4-7d2e-7a31-9b7c-4d6f1e2a3b4c",
  "estimate_micro_usd": 2000000
}
```

Нулевая оценка ничего не удерживает и не возвращает handle. Лимит, уже
превысивший свой предел, всё равно её отклоняет.

| Статус | Значение |
|---|---|
| 200 | Допущено. `handle` пуст, если ничего не удержано. При `"unreachable": "allow"` допуск, который не удалось установить, проходит без удержания с причиной `admission could not be established; admitted without a hold (unreachable=allow)`. |
| 402 | Решение block: у бюджета или лимита расходов с `action=block` нет запаса (`spend_limit` равен true, если отказал лимит на место), набор бюджетов слишком велик для оценки, или арендатор находится под границей активации жизненного цикла попыток либо её состояние не читается. Причина называет случай. |
| 429 | У бюджета с `action=throttle` нет запаса. |
| 503 | Допуск не удалось установить: хранилище бюджетов не прочиталось, ключ остался занят после всех повторов (незавершённой заявкой другого вызова или парой удержаний, опубликованной прежней сборкой, оставшееся удержание которой ещё удерживает), ключ держит заявку, оставленную прежней сборкой, или список причитающихся удержаний ключа не декодируется. Причина: `budget store unreachable (deny-closed)`. |
| 409 | Ключ идемпотентности использован с другим содержимым. |
| 500 | Строка допуска этого ключа не прошла проверку целостности. Ключ отклоняется при любой политике, пока строку не исправят. |
| 400 | Документ нельзя обработать: неизвестная область, отсутствующий ключ, отрицательная оценка или поле, которое схема не публикует. |

402 или 429 из-за лимита — окончательный отказ: не повторяйте то же действие до
нового периода или более высокого лимита. 402 из-за границы активации действует,
пока книгой арендатора владеет жизненный цикл попыток. Отказ 402, 429, 503 или
500 также записывается в аудит как `finops.admission.denied`.

Политика по умолчанию, когда допуск нельзя установить, — **отказ**. Укажите
`"unreachable": "allow"` в документе резервирования, чтобы допустить такой
запрос без удержания: ответ — 200 с причиной выше, а журнал движка записывает
его на уровне ERROR с арендатором, областью, `posture=allow outcome=admitted` и
классом сбоя, но никогда не с собственным сообщением хранилища. Неизвестное
значение означает отказ.

## Правило повтора

- **Резервирование.** Тот же ключ идемпотентности с тем же содержимым в пределах
  окна повтора получает handle первого вызова (`"replayed": true`). Окно длится
  пять минут от ответа, а после подтверждения удержания — от подтверждения. Вне
  окна, а также для вызова, который ничего не удержал, запрос оценивается заново.
- **Подтверждение.** После неопределённого ответа повторяйте `commit` с тем же
  handle и той же суммой столько раз, сколько нужно. Каждый повтор приводит к тем
  же строкам. Другая сумма после подтверждения отклоняется с **409**: действует
  первая измеренная стоимость.
- **Освобождение.** Повторяйте свободно. Освобождение никогда не отменяет
  подтверждение.

## Подтверждение и освобождение

```bash
olivares finops admission commit --data '{"handle":"0192f6c4-7d2e-7a31-9b7c-4d6f1e2a3b4c","actual_micro_usd":1500000}'
olivares finops admission release --data '{"handle":"0192f6c4-7d2e-7a31-9b7c-4d6f1e2a3b4c"}'
```

Загрузите измеренную стоимость до подтверждения, чтобы потолок никогда не
недосчитывал. Документы содержат `handle` и ничего другого, что называло бы
удержание: любое другое поле отклоняется с 400. Пустой handle ничего не
урегулирует.

| Статус | Значение |
|---|---|
| 200 | Урегулировано или уже урегулировано так же. |
| 409 | Другая сумма после подтверждения; удержание, допуск которого всё ещё незавершённая заявка, так что этот handle никто не получил; или удержание, деньги которого теперь принадлежат жизненному циклу попыток (`lifecycle_api_required`). |
| 500 | Строка допуска, называющая удержание, не прошла проверку целостности. Ничего не записано: сохраните загруженную стоимость и повторите тот же вызов после исправления строки. |
| 400 | Handle, который не является идентификатором удержания, или отрицательная сумма. |

`committed: true` и `released: true` означают, что вызов принят, а не что строка
изменилась: подтверждение пустого handle ничего не урегулирует, а освобождение
подтверждённого удержания оставляет его подтверждённым.

## Правило позднего подтверждения

Подтверждение фиксирует, что действие произошло, поэтому принимается, как бы
поздно оно ни пришло: после освобождения, после истечения удержания или после
того, как ключ перехватил другой вызов. Строки удержания становятся
подтверждёнными с измеренной суммой и сохраняют момент, когда удержание
закончилось. Ни один потолок бюджета не меняется, потому что освобождённая или
истёкшая строка ничего не удерживает. Позднее подтверждение истёкшего удержания
уменьшает `expired_unsettled` в следующей сверке.

## Удержания, оставленные прежней сборкой допуска

База данных, в которой работала прежняя сборка допуска, может содержать строки
этой сборки. Ключ, который она допустила под двумя удержаниями, урегулируется
любым из них, и оба урегулируются вместе. Незавершённая заявка, оставленная ею,
снимается только при моменте остановки, который указывает оператор:

```bash
OLIVARES_FINOPS_ADMISSION_LEGACY_WRITERS_STOPPED_AT=2026-09-20T09:00:00Z
```

Укажите момент, когда остановился каждый писатель прежней сборки, во времени
RFC 3339 в UTC с `Z` на конце. Значение читается один раз при запуске.
Восстановление снимает такую заявку только после того, как с этого момента
прошло пять минут, и только пока ни одна строка этих писателей не датирована
позже. Пустое значение (по умолчанию) ничего не снимает. Текст, не являющийся
таким моментом, ничего не снимает и записывает одну ошибку при запуске. Отчёт
показывает состояние в `legacy_stop`: `absent`, `invalid`, `future`,
`contradicted`, `waiting` или `usable`.

## Сверка

Движок запускает восстановление каждую минуту, а задание сверки — каждые пять
минут, для каждого активного арендатора.

```bash
olivares finops admission reconciliation -o json
olivares finops admission reconcile -o json
```

`reconciliation` только читает, с правом чтения бюджетов: ничего не
восстанавливается, не очищается и не регистрируется. `reconcile` — это задание,
с правом записи бюджетов: оно запускает восстановление, очищает удержания,
истёкшие без урегулирования, и регистрирует находку вида
`finops_reservation_drift`, когда `drift` равен true. Консоль показывает тот же
отчёт рядом с бюджетами.

| Поле | Значение |
|---|---|
| `active`, `committed`, `released` | Строки книги в каждом состоянии |
| `expired_unsettled` | Строки, которые никто не урегулировал; TTL вернул запас |
| `active_lapsed` | Истёкшие строки, которые задание ещё не очистило |
| `idempotency_orphans` | Зарезервированные строки допуска, у handle которых нет строк в книге |
| `owed_remaining` | Удержания, всё ещё причитающиеся от незавершённой заявки или опубликованной строки |
| `legacy_pending`, `legacy_owes_release` | Заявки и освобождения, оставленные прежней сборкой |
| `unresolved` | Записи восстановления с ещё не установленным исходом; следующий проход решит заново |
| `undecodable` | Строки допуска, чей список причитающихся удержаний не декодируется |
| `frontier_blocked` | Удержания, которые восстановление не может ни урегулировать, ни отбросить при границе активации |
| `corrupt` | Строки допуска, не прошедшие проверку целостности; они считаются и никогда не записываются |
| `drift` | True, когда `expired_unsettled`, `active_lapsed`, `idempotency_orphans`, `unresolved`, `undecodable` или `corrupt` не равен нулю |

`unresolved` и `frontier_blocked` считает только проход восстановления в
`reconcile`; `reconciliation` сообщает их как 0.

Восстановлению нечего делать для арендатора, когда счётчики от `owed_remaining`
до `corrupt` все равны нулю. Считайте строку `corrupt` нарушением целостности
хранилища этого арендатора и сравните её с последней резервной копией.
Удержания, которые она называет, истекают по TTL; ничто их не урегулирует, пока
строку не исправят.

## Области

| Область | Вызывающая сторона |
|---|---|
| `model_gateway` | Прокси инференса и маршрутизация моделей: резервирует до вызова, затем подтверждает или освобождает |
| `session_launch` | Запуск управляемых сессий и открытие голосового канала |
| `scheduled_job` | Срабатывания оркестрации, судьи оценок и задачи MCP |
