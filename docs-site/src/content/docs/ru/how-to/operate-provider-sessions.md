Сначала выполните [Ваш первый час](/how-to/first-hour/).
Инструменты работают на хосте движка, в том числе внутри контейнера при установке
через Compose. Вход и папки вашего клиентского терминала там автоматически не
доступны.

## Выберите, как инструмент подключается

**Инструменты ИИ** (`/agent-tools`) устанавливает инструменты и запускает их
собственные процессы входа. При нативном движке инструмент по умолчанию использует
собственный вход пользователя движка; учётные записи, вошедшие через Olivares,
остаются отдельными экземплярами. Выберите учётную запись, которую хотите
использовать. Снимок учётной записи показывает адрес электронной почты, тариф,
окна использования и модели, которые сообщает инструмент. Отсутствующие значения
остаются недоступными, а при неудачном обновлении данные помечаются как устаревшие.

**Провайдеры** (`/providers`, раздел **Инструменты**) содержат ключи API и
конечные точки локальных моделей. Добавьте там провайдера и проверьте его, затем
используйте его в разделе «Новая сессия». Ключ провайдера и подписка на инструмент
— разные способы подключения. Ollama требует доступной конечной точки и модели, но
ключ API не нужен. См. [Добавить провайдера](/how-to/add-a-provider/).

Для профилей Claude с `managed_injection`, которые не указывают
провайдера, `OLIVARES_SESSION_RUNTIME_WIF` или `OLIVARES_SESSION_RUNTIME_TOKEN_FILE`
задают общесистемные учётные данные для вывода. Профиль, привязанный к записи
**Провайдеры**, использует эту запись; если её учётные данные нельзя открыть, запуск
отклоняется без перехода к учётным данным хоста. Профиль с `provider_account_home`
использует авторизованный вход инструмента и не требует ни одной из этих переменных.
См. [где применяются переменные окружения](/how-to/add-a-provider/#the-environment-variables-and-where-they-still-apply).

## Начните и ведите разговор

Откройте **Сессии → Новая сессия** и выберите готовый инструмент. Движок заполняет
профиль и папку. Для установки README через Compose выберите **Папка → Другая папка…** и
введите `/project`, чтобы работать с смонтированным проектом на хосте. Если оставить
папку по умолчанию, вводить путь не нужно. Оставьте **Первое сообщение** пустым,
чтобы запустить сессию, а затем печатайте в разговоре или введите сообщение перед
нажатием **Запустить**.

Инструмент, использующий ключ провайдера, применяет сохранённую модель или позволяет
выбрать модель, которую вернула проверка подключения. Если модель обязательна, но
проверка её не вернула, сначала проверьте подключение на странице
**Провайдеры**. Claude Code может использовать свою модель по умолчанию.

Для установки README через Compose запускайте CLI внутри контейнера движка. Он
находит там локальный движок и его сертификат. Входите под учётной записью
администратора Olivares, которую вы создали при настройке, а не под подпиской на
инструмент.

Если вы используете ключ провайдера с инструментом, которому нужна модель (например,
Codex), сохраните модель по умолчанию на странице
**Провайдеры** до выполнения `session start` ниже. Если модель не настроена ни у
провайдера, ни в профиле инструмента, добавьте `--model <tested-model-id>` к команде
`session start`, заменив заполнитель идентификатором модели, который вернула проверка
подключения. Модель, выбранная в **Новая сессия**, действует только для этого запуска
из консоли; она не задаёт модель для запуска из CLI.

Один раз задайте файл Compose в терминале хоста:

```sh
export COMPOSE_FILE="$HOME/olivares/deploy/compose/docker-compose.yml"
docker compose exec olivares olivares login
docker compose exec olivares olivares tool ls
docker compose exec olivares olivares tool providers
docker compose exec olivares olivares session start /project --name first-hour
docker compose exec olivares olivares session send first-hour "Explain this project."
```

Для нативной установки выполняйте те же команды Olivares непосредственно на хосте
движка и замените `/project` на путь к своему проекту. Клиент выводит, какой
инструмент и какое подключение он выбрал. Если инструментов несколько, выберите один
с помощью `--tool`; `--profile` выбирает существующий профиль. Закрытие терминала
клиента не останавливает сессию на движке. Чтобы снова подключиться к её выводу:

```sh
docker compose exec olivares olivares session follow first-hour
```

## Одобрение, прерывание, остановка и возобновление

В разделе **Что может делать агент** пункт **Под контролем** заставляет инструмент
запрашивать разрешение перед действием. В разделе **Правила** ожидающий вас запрос
открыт рядом с очередью, с командой, тем, к чему она обращается, и правилом, которое
запросило разрешение. Выберите **Одобрить один раз** (`A`) или **Отклонить** (`D`) и
добавьте примечание. Запуск, которому нужно одобрение организации, тоже ждёт там;
отправьте сообщение один раз, когда запуск будет одобрен.

Из терминала `olivares session start`, `send` и `follow` показывают тот же запрос, пока выполняется ход, с командой или путём, которые инструмент собирается выполнить. В терминале они спрашивают `Allow? [y/N]` (Enter отклоняет). Без терминала они выводят запрос и команды, которые на него отвечают, с уже подставленным идентификатором: `olivares session approve <session> <request>` или `olivares session deny <session> <request> --note "why"`. Каждая команда отвечает именно на этот запрос и отказывается от запроса, которого сессия уже не ждёт. Движок отклоняет вызов инструмента, если до его срока никто не ответил.

Используйте **Прервать**, чтобы завершить текущий ход и оставить разговор открытым.
Используйте **Остановить**, чтобы завершить процесс; подтвердите, если это потребуется.
**Возобновить** перезапускает ту же сессию с тем же профилем, учётной записью и папкой;
он повторно проверяет учётные данные и политику. После возобновления отправьте новое
сообщение.

```sh
docker compose exec olivares olivares session interrupt first-hour
docker compose exec olivares olivares session stop first-hour
docker compose exec olivares olivares session resume first-hour
docker compose exec olivares olivares session send first-hour "Continue explaining this project."
```

Изменённая или недоступная учётная запись приводит к отказу в запуске, а не к
разрешению переключиться на другой вход. Прерванный ход Grok использует отмену ACP
без подтверждения; прежде чем считать ход завершённым, дождитесь коррелированного
результата хода.

## Получайте уведомления, когда сессия ждёт вас, при закрытой вкладке

В **Настройках**, в разделе **Уведомления о сессиях**, выберите **Уведомлять меня**. Пока вкладка консоли открыта в фоне, браузер сообщает вам, как и раньше. В браузере с поддержкой Web Push тот же переключатель также регистрирует этот браузер в вашем движке, поэтому сессия, которую вы запустили и которая запрашивает одобрение или завершается, доходит до него при закрытой вкладке. Нажмите на уведомление, чтобы открыть эту сессию; её запрос на одобрение ждёт там. Выключение переключателя удаляет регистрацию. Один человек может зарегистрировать до 10 браузеров; самый старый уходит, когда регистрируется одиннадцатый.

Чтобы установить консоль, используйте собственное действие браузера **Установить** или **Добавить на главный экран**. На Android Chrome предлагает **Установить приложение**. На iPhone или iPad уведомления работают только из установленного приложения: нажмите **Поделиться**, затем **На экран «Домой»**, откройте Olivares с главного экрана и включите переключатель там. К движку нужно обращаться по HTTPS, который браузеры требуют для установленных приложений и для push. При встроенном локальном сертификате движка консоль сохраняет уведомления в открытой вкладке и не использует Web Push. Для уведомлений при закрытой вкладке используйте доверенный сертификат TLS или обратный прокси, который завершает TLS.

Движок отправляет каждое уведомление, зашифрованное ключом вашего браузера. Google, Mozilla или Apple управляют службой push, которая его передаёт; эта служба видит зашифрованное тело и время отправки, но не текст. Уведомление содержит имя, которое вы дали сессии, либо ничего, и фиксированную фразу на вашем языке; оно никогда не содержит того, что написала сессия. Вашему движку нужно достучаться до службы push на порт 443; если не может, переключатель всё равно работает для открытых вкладок, а в «Настройках» сказано, что это устройство не удалось зарегистрировать.

## Необязательные настройки профиля и git

Для существующего настроенного домашнего каталога инструмента вкладка
**Профили провайдеров** раздела **Сессии** (`/sessions?tab=profiles`) позволяет
администратору зарегистрировать профиль и проверить готовность к запуску. Профиль
именованной учётной записи и её привязки источников также указаны в её сведениях в
разделе **Инструменты ИИ**. Домашние каталоги должны существовать на хосте выполнения.
Чтобы выбрать этот профиль, в разделе «Новая сессия» используйте **Ещё → Расширенные
параметры запуска**. Переопределения двоичных файлов выбирают исполняемый файл;
в противном случае движок использует самую новую проверенную управляемую установку,
а затем инструмент из своего `PATH`. См. [Конфигурация](/reference/configuration/).

Для верхней папки git-репозитория, в котором есть хотя бы один коммит, **Работать в
новом git worktree** создаёт для сессии ветку и рабочий каталог. Возобновление
использует их повторно. Передача с веткой и коммитом предлагает **Открыть в worktree
новой сессии**; выберите зарегистрированную папку, репозиторий которой содержит этот
коммит. Движок отказывает в неподдерживаемых или небезопасных настройках репозитория
до создания worktree.

Папка может хранить одну команду настройки для новых worktree. Человек должен
одобрить её точный текст по SHA-256, прежде чем запуск worktree будет принят;
изменение даже одного символа требует нового одобрения. Одобренная команда выполняется
один раз в новом worktree перед первым ходом сессии; ошибка останавливает запуск и
показывает вывод. Если настройка завершилась ошибкой, resume выполняет команду снова;
после успешной настройки или запуска с зафиксированным `--no-setup` она повторно не выполняется.
См. [Одобрение команды настройки папки](/reference/session-runtime-api/#approving-a-folders-setup-command).

Очистка не удаляет незакоммиченную или неслитую работу. **Также отбросить worktree и
ветку** явно разрешает такую потерю; игнорируемые файлы удаляются вместе с worktree.
Worktree используют общие метаданные git репозитория. Параметры worktree см. в
[справочнике CLI для сессий](/reference/cli/#command-olivares-session-start), а профили
разрешений, вызовы жизненного цикла и ограничения изоляции — в
[API среды выполнения сессии](/reference/session-runtime-api/).
