Эта страница — путь **эксплуатации** официальных CLI провайдеров. Плоскость
управления запускает собственный дочерний процесс под **профилем провайдера**.
Она не устанавливает провайдера, не создаёт его home и не открывает
интерактивный вход в браузере.

Это не путь коннектора или hook. Чтобы инвентаризировать или управлять
файлами конфигурации Grok Build или Codex, используйте
[Интеграция Grok Build](/how-to/integrations/grok/) или
[Интеграция Codex](/how-to/integrations/codex/). Чтобы совместно разместить
Claude Code на том же хосте, используйте
[Запуск Claude Code с Olivares](/how-to/run-claude-code-with-olivares/).

Источник этого поведения: раздел `[26.9.0]` в `CHANGELOG.md` (профили
провайдера, драйвер Codex, драйвер Grok), сгенерированные справочники
[консоли](/reference/console/) и
[конфигурации](/reference/configuration/), `cmd/olivares/sessionruntime.go`
и `web/src/features/agentops/types.ts`.

## Предусловия

Выполните их до запуска. Отсутствующий пункт — отказ, а не запасной путь.

1. Olivares AI установлен, и первый администратор существует.
   См. [Ваш первый час](/how-to/first-hour/) про токен установки и барьер
   AAL3 passkey. Создание источников и привилегированные операции сеанса
   требуют AAL3 (`core/api/middleware.go` `requireAAL3`).
2. Официальная CLI провайдера уже установлена на **этом узле**. Профиль
   регистрирует home, которые уже существуют. Сервер разрешает пути
   (абсолютные, символические ссылки разрешены, существующий каталог) и не
   создаёт, не устанавливает и не входит
   (`web/src/features/agentops/types.ts` `CreateProfileRequest`).
3. У вас есть `sessions:profile:read`, чтобы открыть **Provider profiles**
   (`/provider-profiles`), и `sessions:profile:write` для регистрации.
   Привязка источника требует `sessions:profile-binding:write` плюс
   администрирование источников. Запуск требует `sessions:run:write`.
   Права: [справочник консоли](/reference/console/).
4. Соответствующий драйвер **зарегистрирован на этом узле** закреплением
   его официального двоичного файла. Готовность — по драйверу. Общего
   переключателя нет (`cmd/olivares/sessionruntime.go`).

| Драйвер | Закрепите эту переменную окружения | Если не задана |
|---|---|---|
| Claude Code | `OLIVARES_SESSION_RUNTIME_CLAUDE_BIN` (по умолчанию `claude`) | путь Claude использует имя исполняемого файла по умолчанию |
| Codex | `OLIVARES_SESSION_RUNTIME_CODEX_BIN` | Если не задана, **зарегистрированная** управляемая установка (`olivares agent tool install --driver codex`) закрепляет исполняемый файл из квитанции. Иначе профили Codex остаются наблюдаемыми и не запускаются. Движок не ищет в `PATH`. |
| Grok | `OLIVARES_SESSION_RUNTIME_GROK_BIN` | Если не задана, **зарегистрированная** управляемая установка (`olivares agent tool install --driver grok`) закрепляет исполняемый файл из квитанции. Иначе профили Grok остаются наблюдаемыми и не запускаются. Движок не ищет в `PATH`. |

Значение — официальный двоичный файл, которым этот узел может управлять.
Движок не разрешает `codex` или `grok` из `PATH`. Сгенерированная таблица
конфигурации также перечисляет `OLIVARES_SESSION_RUNTIME_OPENCODE_BIN` с тем
же правилом регистрации; эта страница не добавляет других утверждений об
OpenCode.

Запускам Claude по-прежнему нужен источник учётных данных вывода
(`OLIVARES_SESSION_RUNTIME_WIF` или `OLIVARES_SESSION_RUNTIME_TOKEN_FILE`).
См. [Ваш первый час](/how-to/first-hour/).
Codex и Grok используют только AUTHORIZED `auth_source` профиля:
`provider_account_home` или `managed_injection`, без запасного пути и без
значения по умолчанию (`CHANGELOG.md` `[26.9.0]`; `ProviderProfileDTO.auth_source`).

:::caution[Что эта страница не утверждает]
`CHANGELOG.md` `[26.9.0]` указывает, что поведение драйвера Grok доказано
против собственного поддельного ACP-потомка через реальные HTTP, runtime,
хранилище и группу процессов. **Совместимость с аутентифицированной
официальной учётной записью Grok — отдельная работа и здесь не утверждается.**
:::

## 1. Зарегистрировать профиль провайдера

Профиль провайдера — устойчивая идентичность **одного** настроенного
экземпляра провайдера на **одной** среде выполнения: драйвер, владеющая
среда и канонические `config_home` / `user_home`, под которыми работает
потомок. Это идентичность конфигурации и хранения, а не аутентифицированная
учётная запись провайдера (`CHANGELOG.md` `[26.9.0]` B1; текст консоли
`agentops.profiles.subtitle`).

### Консоль

1. Откройте **Provider profiles** (`/provider-profiles`).
2. Выберите **Register profile**.
3. Укажите драйвер (`claude`, `codex` или `grok`), существующий `config_home`
   и существующий `user_home`. `environment_ref` можно опустить (этот узел).
4. Сохраните. Список показывает `profile_ref`, драйвер, состояние и включён
   ли профиль в этой среде. Пути **не** входят в обычный список.
5. Чтобы увидеть сохранённые home, используйте **Reveal configuration**
   (`sessions:profile:admin`). Это чтение по требованию и сбрасывается при
   скрытии. Значения учётных данных по-прежнему нет.

Переименование, отключение и включение сохраняют тот же id и те же home.
**Retire** необратим, подтверждается вводом и освобождает home для **нового**
id.

### Что движок отказывает

- Профиль, драйвер которого не зарегистрирован на этом узле, остаётся видимым
  и не запускается (`operable` не гарантия запуска;
  `GET …/launch-readiness` — панель требований).
- Профиль другой среды выполнения показан как чужой и никогда не запускается
  с этого узла.
- Запуск, который передаёт `HOME`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или
  `GROK_HOME`, отклоняется. Эти имена принадлежат профилю
  (`agentops.create.profileEnvConflict`).

Снимка этого экрана в опубликованном наборе нет. Не считайте изображение
вкладки Connectors этой формой.

## 2. Привязать источник (необязательно, для наблюдаемой атрибуции)

Источник можно закрепить за профилем на точной ревизии roster, которую
применил этот узел. Ключ — постоянный id строки, никогда редактируемое имя
(`CHANGELOG.md` `[26.9.0]` B1; **Source bindings** `/provider-bindings`).

1. Откройте **Source bindings** (`/provider-bindings`).
2. Привяжите постоянный `id` источника и `applied_revision`, которую
   подключил reconciler этого узла. `GET /v1/console/sources` сообщает оба.
3. Отзовите привязку, чтобы остановить **новую** атрибуцию профиля. Более
   ранний конверт сохраняет историческую привязку при воспроизведении.

Без привязки известная регистрация всё ещё появляется как строка наблюдения
`source`. Она не сливается в управляемый запуск. См.
[Живая эксплуатация и сеансы](/reference/modules/ii-sessions/).

## 3. Запуск

Продуктивная конечная точка создания требует `provider_profile_ref`. Если её
опустить, остаётся старое тело запроса, которое этот API отклоняет
(`CHANGELOG.md` `[26.9.0]` B2; флаг CLI `--provider-profile`).

Диалог запуска предлагает **активные** профили. Профиль не предвыбирается.
Выборы workspace и template можно очистить; профиль нельзя
(`CHANGELOG.md` `[26.9.0]` Fixed).

### Консоль

1. Откройте **Operate sessions** (`/agentops`) или **Observe sessions**
   (`/sessions`). Они делят экран
   ([справочник консоли](/reference/console/)).
2. Откройте диалог запуска.
3. Выберите **Provider profile** (`agentops.create.profile`). Подсказка
   указывает, что профиль обязателен.
4. При желании задайте workspace, template, model и effort. Для Grok model и
   effort остаются открытыми строками провайдера на официальных флагах агента
   (`CHANGELOG.md` `[26.9.0]`).
5. Отправьте **Request launch**. Публикуется только **ссылка** профиля.
   Сервер разрешает home.

### CLI

```sh
olivares agent session create --provider-profile <profile_ref>
```

Добавьте `--server`, `--tenant` и `--token` (или активный клиентский
контекст), как в [справочнике CLI](/reference/cli/). Изоляция в этом выпуске
— `native`; `container` и `sandbox` API принимает, а запускатель отклоняет,
пока этих исполнителей нет (сгенерированная справка CLI).

Результат: ресурс запуска. Управляемая живая строка уникальна по области
наблюдения и внешнему id. Чтения, которые называют строку, используют
`live_ref`, а не голый id сеанса провайдера, который могут разделять два home.

## 4. Прервать или остановить

| Намерение | Консоль | CLI | Результат |
|---|---|---|---|
| Завершить активный ход, сохранить процесс и беседу | управление interrupt живого сеанса | `olivares agent session interrupt <run-ref>` | ход заканчивается; процесс остаётся пригоден для следующего (`CHANGELOG.md` `[26.9.0]`) |
| Завершить запуск | управление stop | `olivares agent session stop <run-ref>` | ресурс запуска; runtime по-прежнему собирает потомка |

Запуски, связанные с работой, отправляют точное ограждение аренды. Устаревшие
или неопределённые результаты остаются явными. Возобновление продолжается
только на том же доказанном home.

Прерывание Grok использует ACP `session/cancel` — уведомление без
подтверждения. Прерывание разрешает ожидающие согласования, отменяет и
оставляет ход открытым, пока не вернётся коррелированный результат самого
prompt (`CHANGELOG.md` `[26.9.0]`). Не считайте тихое отменение
подтверждённой квитанцией провайдера.
