Эта страница описывает **v26.9.0 в том виде, в котором она поставляется**. Это
не запланированный мастер первого запуска и не снимок экрана макета. Каждый
приведённый ниже шаг — это то, что публичный бинарный файл делает сегодня, с
указанием файла или переменной окружения, которые обеспечивают это поведение.
Там, где продукт отказывает, страница сообщает об этом.

Пронумерованные факты были измерены 2026-09-04 на чистой установке публичного
бинарного файла. Эта страница ссылается на эти измерения и на код, до которого
доходят соответствующие пути выполнения.

Установка бинарного файла на хост описана в разделах
[Самостоятельное размещение Olivares AI](/how-to/self-hosting/) и
[Проверка релиза](/how-to/verify-a-release/). Эта страница не предлагает
передавать `https://olivares.ai/install` через pipe в shell. Когда бинарный
файл уже находится на хосте, рекомендуемая первая команда —
`olivares quickstart`.

:::note[Чем это не является]
`--seed-demo` — не обзорная экскурсия по продукту. Измерено 2026-09-04 на
чистой установке публичного бинарного файла: после загрузки с демонстрационными
данными **36 из 54** маршрутов консоли по-прежнему пусты. Это перепись даты
измерения. Сгенерированный
[справочник консоли](/reference/console/) в этом дереве перечисляет
**75 маршрутов**. Эта страница не пересчитывает пустые вкладки после
`--seed-demo` на v26.9.0. Демонстрационное окружение заполняет сценарий графа
доступа в руководстве
[От нуля до графа доступа для чтения/записи](/tutorials/zero-to-graph/), но не
остальную часть консоли. Не используйте его для «изучения продукта».
:::

## 1. Рекомендуемый запуск: `olivares quickstart`

В новом каталоге данных **нет учётных данных по умолчанию**. Рекомендуемая
первая команда — `olivares quickstart` (`cmd/olivares/cmd_quickstart.go`). Это
`serve` с безопасными настройками по умолчанию: TLS включён, прослушивание
учётных данных по умолчанию нет, токен настройки одноразовый. Адрес прослушивания по
умолчанию — `:8443`, то есть все интерфейсы, потому что это сервер
(`cmd/olivares/binddefaults.go`). Измерено 2026-09-04 на чистой установке
публичного бинарного файла с настоящим TLS (включая запуск на **:8460**); текст
панели тот же.

Панель приветствия (`announceQuickstart`, `:154-163`) пронумерована. Движок
выводит для этой привязки `https://localhost:8443` и перечисляет под токеном все
остальные адреса, на которых отвечает этот хост. **Не используйте IP-адрес для
церемонии passkey.**
Браузер отклоняет IP-адрес в качестве WebAuthn RP ID (`SecurityError`). Продукт
выводит RP ID из имени хоста запроса (`core/api/handlers_webauthn.go:33-50`).
Перед регистрацией passkey откройте консоль по адресу
`https://localhost:PORT` (или по настоящему имени хоста), а не
`127.0.0.1`. `PORT` равен `8443`, если вы не передали `--listen`.

```text
=== WELCOME TO OLIVARES AI ===
  1. Open:   https://localhost:8443
     (HTTPS with a self-signed certificate on first boot — your browser will
      warn once; that is expected for a local install.)
  2. Complete setup with this one-time token (shown once, single-use):

         olst_…
```

Баннер печатает `localhost` для привязки по умолчанию и перечисляет под токеном
остальные адреса этого хоста; церемонии passkey нужно имя, а не адрес. Замените хост
на `localhost` в адресной строке.

Префикс токена — `olst_` (`cmd/olivares/e2e_binary_test.go` проверяет
соответствие `olst_[A-Z0-9]+`). Страница консоли — `/setup`. API, куда мастер
отправляет запрос:

```http
POST /v1/setup
Content-Type: application/json

{"token":"olst_…","email":"you@example.com","password":"…"}
```

`olivares serve` печатает похожий баннер (`announceSetup` в
`cmd/olivares/cmd_serve.go`). В первый час используйте `quickstart`: URL,
предупреждение о самоподписанном сертификате и одноразовый токен находятся на
одной панели. Затем войдите через `POST /v1/auth/login`. Теперь у вас есть
сессия с паролем уровня AAL1.

`README.md` и эта панель приветствия называют токен и URL. Они **не** называют
регистрацию passkey. Она идёт следующим шагом в консоли после нажатия кнопки.

## 2. Барьер AAL3 — консоль направляет вас после нажатия, а не до него

После установки **создание источников, коннекторов, рабочих пространств и
секретов отклоняется, пока сессия не достигнет AAL3**. Барьер — `requireAAL3` в
`core/api/middleware.go:310`. Principal ниже AAL3 получает `403
step_up_required`. Через этот барьер проходят **21 место вызова**. Пути
записи в этом дереве включают:

| Поверхность | Handler | Файл |
|---|---|---|
| Добавление/удаление/перезагрузка реестра источников | `handlePutSource` / `handleDeleteSource` / `handleReloadRuntime` | `core/api/handlers_sources.go` |
| Запись и тестирование коннекторов | `handlers_connectors.go` | `core/api/handlers_connectors.go` |
| Добавление/удаление секрета | `handlePutSecret` / `handleDeleteSecret` | `core/api/handlers_secrets.go` |
| Создание/обновление рабочего пространства | `handleCreateWorkspace` / `handleUpdateWorkspace` | `core/api/handlers_scoping.go:152` / `:199` |
| Подключение участника | `handleOnboardMember` | `core/api/handlers_onboarding.go:59` |

**PIV/CAC не позволяет достичь этого уровня в стандартной установке.** Без
настройки маршруты PIV отвечают **501** `piv_not_configured`
(`core/api/handlers_piv.go`, `core/api/errors.go`).

### Что на самом деле делает консоль

Консоль **действительно** направляет вас к регистрации. Она делает это
**реактивно**.

1. Вы пытаетесь выполнить привилегированное действие. На панели усиленной
   аутентификации отображается **Аутентификация с ключом безопасности**
   (`web/src/features/identity/i18n/en.json` `assurance.authenticate`; кнопка в
   `web/src/features/identity/assurance.tsx:230-239`).
2. Нажатие вызывает `POST /v1/auth/webauthn/authenticate/options` (усиленная
   аутентификация, не регистрация). Если passkey отсутствует, движок отвечает
   **400** `no_webauthn_credential` (`isNoWebAuthnCredential` в
   `web/src/features/identity/api.ts:260-265`).
3. Затем панель предлагает сначала зарегистрироваться на вкладке
   **Привилегированный вход** (`assurance.tsx:160-168` →
   `assurance.unenrolled`). Это предложение **не является ссылкой**.

Перейдите туда вручную:

1. Откройте консоль по адресу **`https://localhost:PORT`**, а не
   `127.0.0.1` (см. §1).
2. Откройте `/identity` (`web/src/features/registry.tsx` —
   `path: '/identity'`).
3. Вкладка **Привилегированный вход** (`tabs.login`).
4. **Зарегистрировать passkey** (`passkeys.register`). Достаточно
   **платформенного аутентификатора** (запрос браузера или ОС; физический ключ
   не требуется). Сервер **требует проверки пользователя**
   (`core/auth/webauthn.go:74-85`, `UserVerification: VerificationRequired`).
   Измерено 2026-09-04 на чистой установке публичного бинарного файла с полной
   церемонией WebAuthn: регистрация **200**, аутентификация `{"aal":3}`, затем
   `PUT /v1/console/connectors` **200**.

`POST /v1/auth/webauthn/register/options` аутентифицируется как **principal
сессии** и **не** вызывает `requireAAL3`. В случае успеха он записывает **200**
с `{publicKey: …}` (`core/api/handlers_webauthn.go:76-88`). Завершите церемонию
через `POST /v1/auth/webauthn/register`, затем повторите усиленную
аутентификацию.

`README.md` и панель приветствия `olivares quickstart` **не** называют вкладку
«Привилегированный вход». Консоль называет её только **после** этого ответа 400.

Панель identity называет AAL3 (NIST SP 800-63B-4) и PIV/CAC (FIPS 201-3)
**целевыми стандартами** и утверждает, что **не заявляет о сертификации**
(`targetStandardsNote`). Эта страница также не заявляет о сертификации.

### Добавить коннектор: барьер без полей

**Добавить коннектор** (`web/src/features/console/i18n/en.json`
`connectors.add`) открывает диалог, где
`<RequireAssurance minAal={AAL.HARDWARE}>` оборачивает `ConnectorForm`
(`web/src/features/console/connectors-tab.tsx:348-357`). Ниже AAL3 форма не
монтируется. Измерено 2026-09-04 на чистой установке публичного бинарного файла:
в этом диалоге **нет полей ввода** (`inputs: []`) — только панель усиленной
аутентификации. Каталог типов виден на AAL1 (`ConnectorCatalog` находится вне
барьера, тот же файл `:341-346`); **добавление** коннектора на AAL1 недоступно.

### `/workspace` и привязки протоколов: переключателя рабочего пространства нет

Для `/workspace` (`registry.tsx` `path: '/workspace'`) и
`/communications/protocol-bindings` требуется рабочее пространство. В чистой
установке его нет, и создать его до достижения AAL3 нельзя
(`handleCreateWorkspace`). `WorkspaceSwitcher` **не отображается**, когда
существует не более одного рабочего пространства
(`web/src/components/layout/workspace-switcher.tsx:43-44`:
`if (workspaces.length <= 1) return null`). В верхней панели остаётся
**Сменить организацию** (`web/src/lib/i18n/locales/en/auth.json`
`tenant.switch`). Переключателя рабочего пространства, по которому можно было
бы нажать, нет.

## 3. Запуск сессии Claude Code из консоли

Консоль может запустить процесс `claude`, только если на **хосте** есть
источник учётных данных для инференса. Без него запуски stream-json
отклоняются по принципу deny-closed. Измерено 2026-09-04 на чистой установке
публичного бинарного файла: **HTTP 503**.

Задайте **одну** из следующих переменных:

- `OLIVARES_SESSION_RUNTIME_WIF` — выпуск WIF внутри процесса (`cmd/olivares/sessionruntime.go`, `cmd/olivares/wifbroker.go`)
- `OLIVARES_SESSION_RUNTIME_TOKEN_FILE` — путь к ротируемому короткоживущему файлу токена

Корень композиции записывает в лог подключённый источник либо:

```text
session runtime: no inference credential source configured; stream-json launches are deny-closed
```

(`cmd/olivares/sessionruntime.go:74-76`). Необязательные связанные переменные:
`OLIVARES_SESSION_RUNTIME_WIF_RULE`, `OLIVARES_SESSION_RUNTIME_TOKEN_TTL`,
`OLIVARES_SESSION_RUNTIME_BASE_URL`, `OLIVARES_SESSION_RUNTIME_CLAUDE_BIN`
(перечислены в `cmd/olivares/config_registry.go` и разделе
[Конфигурация](/reference/configuration/)).

Схемы совместного развёртывания **Operate** (на одном хосте с `claude`)
описаны в разделе
[Запуск Claude Code с Olivares](/how-to/run-claude-code-with-olivares/). Путь
наблюдения OTLP описан в разделе
[Подключение Claude Code](/how-to/connect-claude-code/).

### Ключи провайдера не запускают сессию

**Модели → Ключи провайдера** — реестр управления **ссылками**. Форма
**никогда не принимает секрет**:

> Эта форма никогда не принимает секрет. Olivares хранит только ссылку и
> маскированную подсказку.

(`web/src/features/models/i18n/en.json` `keys.dialog.noSecretNote`). Заполнение
этой вкладки не удовлетворяет требованиям `OLIVARES_SESSION_RUNTIME_WIF` или
`OLIVARES_SESSION_RUNTIME_TOKEN_FILE`. Оно не разрешает запуск сессий.

## 4. План развёртывания отвечает 503, пока вы не подготовите executor

Операции plan/apply по `POST` в модуле развёртывания возвращают **503**, пока
на хосте не будет задан путь к JSON-файлу в
`OLIVARES_DEPLOY_EXECUTOR_CONFIG`. При отсутствии переменной модуль сохраняет
неподключённый executor, работающий по принципу deny-closed
(`cmd/olivares/deployexec_load.go:16-20`). Нечитаемый файл приводит к
**ошибке запуска**.

Объект JSON — `deployExecutorConfig` в
`cmd/olivares/deployexec_load.go:26-42`. Необязательные блоки backend:
`tofu`, `terraform`, `gitops`, `k8s`, `docker`, `nomad`, `crossplane`, а также
`credential`, `blast_radius`, `identity_binding`, `drift`.

Переменная окружения описана в разделе
[Конфигурация](/reference/configuration/)
(`docs-site/src/content/docs/reference/configuration.md:152`). Она не описана
как действие в консоли в первый час. В UI нет варианта, который заменяет этот
файл.

В каталоге модулей actuation для Deployment помечена как **on-demand (503)**
([Модули](/reference/modules/overview/)). Эта строка выражает тот же факт.

## 5. Запрос к публичной базе знаний или запрос с identity агента

Embedder по умолчанию — **LocalHashEmbedder**, не создающий исходящего трафика.
При запуске выводится предупреждение, что поиск **лексический, а не
семантический**, и `embed_model=local-hash`
(`cmd/olivares/claude_inference.go`, `cmd/olivares/knowledgestatus.go`).
Лексический поиск всё же возвращает фрагменты, когда барьер разрешает их.

Без аутентифицированной identity агента барьер поиска разрешает только
**публичный контент без ограничений** (`modules/knowledge/query.go:120-127`).
REST-запрос человека к `/query` для **внутренней** базы знаний отклоняется.
Измерено 2026-09-04 на чистой установке публичного бинарного файла: **публичная**
база знаний вернула **1 результат** (оценка 0.738). Запрашивайте публичную базу
знаний или используйте identity агента.

Сегодня отклонённый запрос сообщает `excluded_chunks: 0`, даже если было
исключено всё. Этот счётчик увеличивается только для заданного оператором
нижнего предела `excluded_sources` (`query.go:256-284`); отказ по уровню допуска
или ACL никогда не увеличивает его.

## 6. Сеансы Codex и Grok: профили провайдера, затем оставшиеся CLI-хуки

v26.9.0 управляет официальной CLI Codex и официальной CLI Grok как драйверами
сеанса, в дополнение к Claude Code (`CHANGELOG.md` `[26.9.0]` Added). Консоль
администрирует эти запуски на **Provider profiles** (`/provider-profiles`,
`sessions:profile:read`) и **Source bindings** (`/provider-bindings`,
`sessions:profile-binding:read`). Оба маршрута есть в сгенерированном
[справочнике консоли](/reference/console/).

Профиль — устойчивая идентичность одного настроенного экземпляра провайдера
на одной среде выполнения. Это не аутентифицированная учётная запись провайдера
(`web/src/features/agentops/types.ts`). Регистрация проверяет home, которые уже
есть на этом узле. Сервер не устанавливает, не создаёт и не входит.

### Зарегистрировать драйвер на хосте до запуска

Готовность — по драйверу. Общего переключателя нет
(`cmd/olivares/sessionruntime.go`). Соответствующая переменная окружения
регистрирует этот драйвер на этом узле:

| Драйвер | Переменная окружения | Если не задана |
|---|---|---|
| Claude Code | `OLIVARES_SESSION_RUNTIME_CLAUDE_BIN` (по умолчанию `claude`) | путь Claude использует имя по умолчанию |
| Codex | `OLIVARES_SESSION_RUNTIME_CODEX_BIN` | профили Codex остаются наблюдаемыми и не запускаются |
| Grok | `OLIVARES_SESSION_RUNTIME_GROK_BIN` | профили Grok остаются наблюдаемыми и не запускаются |

Значения — закреплённые официальные двоичные файлы. Движок не разрешает
`codex` или `grok` из `PATH`. Источник: [Конфигурация](/reference/configuration/).

Запускам Claude по-прежнему нужен источник учётных данных вывода, как в §3.
Codex и Grok аутентифицируются AUTHORIZED `auth_source` профиля
(`provider_account_home` или `managed_injection`, без запасного пути).
`CHANGELOG.md` `[26.9.0]` **не** утверждает совместимость с аутентифицированной
официальной учётной записью Grok.

Диалог запуска требует профиль провайдера. Продуктивная конечная точка
создания требует `provider_profile_ref`. Если её опустить, остаётся старое тело
запроса, которое этот API отклоняет ([CLI](/reference/cli/)
`olivares agent session create --provider-profile`).

Как зарегистрировать профиль, привязать источник, запустить, прервать и
остановить: [Управлять сеансом провайдера](/how-to/operate-provider-sessions/).

### Что остаётся только в CLI (хуки и управляемая конфигурация)

Эти команды не являются запуском сеанса из консоли. Они по-прежнему существуют:

| Команда | Назначение | Источник |
|---|---|---|
| `olivares codex` | Формирует Codex `requirements.toml` / `managed_config.toml` из JSON Policy. **Записывает файлы; не обращается к плоскости управления.** | `cmd/olivares/cmd_codexmanagedconfig.go` |
| `olivares codex-hook` | Deny-closed PEP hook, который вызывает Codex (stdin → плоскость управления → stdout в форме события). | `cmd/olivares/cmd_codexhook.go` |
| `olivares grok-hook` | Deny-closed PEP hook, который вызывает Grok Build. Отказ **блокирует** только на `pre_tool_use`. | `cmd/olivares/cmd_grokhook.go` |

При установке hook Codex (форма `hooks.json` Codex проверена по комментарию в
этом файле) `command` должен быть **строкой**: `olivares codex-hook`.
Переменные окружения: `OLIVARES_CODEX_HOOK_URL`,
`OLIVARES_CODEX_HOOK_TOKEN`, `OLIVARES_CODEX_HOOK_TENANT` (необязательно также
agent/org/account).

Переменные окружения hook Grok: `OLIVARES_GROK_HOOK_URL`,
`OLIVARES_GROK_HOOK_TOKEN`, `OLIVARES_GROK_HOOK_TENANT`. Grok может отключить
hook по имени через `~/.grok/disabled-hooks`; это не элемент управления в
консоли.

Не ищите **кнопку** «Подключить Codex» или «Подключить Grok». Зачисление
коннектора — **Control console → Connectors** (тип `codex` или `grok`). Это
плоскость наблюдения/управления в
[Интеграция Codex](/how-to/integrations/codex/) и
[Интеграция Grok Build](/how-to/integrations/grok/). Она не регистрирует
драйвер сеанса.

## 7. `--seed-demo` не заполняет консоль

`olivares serve --seed-demo` загружает демонстрационное окружение, чтобы можно
было пройти руководство по графу доступа. Измерено 2026-09-04 на чистой
установке публичного бинарного файла: **36 из 54** экранов консоли по-прежнему
пусты в этом окружении. Это перепись даты измерения; сгенерированный справочник
консоли сегодня перечисляет **75 маршрутов**. Используйте `--seed-demo` только
для сценария из раздела
[От нуля до графа доступа для чтения/записи](/tutorials/zero-to-graph/). Не
считайте пустые вкладки после `--seed-demo` признаком сломанной установки и не
считайте этот флаг экскурсией по продукту.
