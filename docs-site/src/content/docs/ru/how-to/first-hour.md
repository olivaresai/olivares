Понадобятся Docker Compose, папка проекта, с которой инструмент должен работать,
и одно из: подписка на инструмент, ключ API провайдера или локальная модель.

## 1. Установите и откройте консоль

Следуйте [установке из README](https://github.com/olivaresai/olivares#install).
Установщик явно выбирает образ релиза, монтирует папку вашего проекта на хосте
в `/project` и выводит адрес консоли и новый одноразовый токен настройки.
Если на вашем хосте Docker применимы инструкции по AppArmor, используйте их там же.

Откройте выведенный адрес. Первая установка использует самоподписанный сертификат;
прежде чем принять предупреждение браузера, убедитесь, что вы открываете свой
сервер. Введите токен настройки, адрес электронной почты и пароль, чтобы создать
первого администратора. Храните токен и пароль в тайне. Консоль выполнит вход и
откроет мастер настройки.

Контейнер запускает инструменты на сервере. Инструмент, вошедший в систему на
вашем ноутбуке, относится к другой установке; его вход в контейнер не копируется.

## 2. Выберите инструмент и его вход

Воспользуйтесь мастером или откройте **Инструменты ИИ** (`/agent-tools`). Для
каждого инструмента показано, установлен ли он и выполнен ли вход. Если он не
установлен, проверьте и одобрите его установку. Используйте элемент входа
инструмента и пройдите его собственный процесс входа. Для Claude Code или Codex
одобрите вход с вашей учётной записью Claude или ChatGPT.

При нативной установке инструмент по умолчанию использует вход пользователя,
который запускает движок. Входы, выполненные через Olivares, остаются отдельными
экземплярами. Инструменты показывают учётную запись, тариф, модели и окна
использования, которые они предоставляют. Недоступное значение не равно нулевому
остатку; при неудачном обновлении последний снимок отмечается как устаревший с
указанием команды, которая не выполнилась.

Чтобы вместо этого использовать ключ API, откройте **Инструменты**, добавьте
провайдера в разделе **API-ключи** и проверьте подключение. Для локальной модели
добавьте конечную точку Ollama, доступную из движка; ключ API при этом не нужен.
См. [Добавить провайдера](/how-to/add-a-provider/). Если инструменту нужна модель,
как Codex, выберите одну из моделей, которую вернула проверка подключения, когда у
провайдера нет сохранённой модели по умолчанию. Claude Code может использовать
свою модель по умолчанию.

## 3. Начните сессию в вашем проекте

1. Откройте **Сессии** (`/sessions`) и выберите **Новая сессия**.
2. Выберите готовый инструмент. В форме показана папка, и она заполняется
   автоматически. Оставьте её как есть для сессии в собственной папке или выберите
   **Сменить папку** и введите `/project`, чтобы использовать папку на хосте,
   смонтированную установщиком README.
3. Оставьте поле **Первое сообщение** пустым и нажмите **Запустить**. Сообщение
   можно ввести в разговоре после его открытия. Профиль и домашние пути заполняет
   движок; регистрировать их для этой первой сессии не нужно.

Пользователь контейнера, UID 65532, должен иметь право записи в проект на хосте.
В [инструкциях по папке проекта](https://github.com/olivaresai/olivares/blob/main/deploy/compose/README.md#work-on-a-host-project-folder)
описаны права доступа. Сессия может менять содержимое смонтированной папки;
используйте каталог проекта, а не всю домашнюю папку.

Попросите инструмент объяснить проект. Прочитайте его ответ в разговоре.
Если **Запустить** не может продолжить, форма называет, чего не хватает. Выполните
это указание в **Инструментах**, затем вернитесь к сессии.

## 4. Одобрите действие

Чтобы опробовать одобрение, при запуске сессии выберите **Ещё → Спрашивать перед
каждым действием**. Попросите инструмент выполнить безвредную команду в проекте.
Когда он запросит разрешение, откройте **Правила**. Ожидающий вас запрос выделен
оранжевым и открыт рядом с очередью: там видны команда, то, к чему она обращается,
и правило, которое запросило разрешение. Выберите **Одобрить один раз** (или
нажмите `A`) либо **Отклонить** (`D`) и добавьте примечание. Вернитесь в разговор,
чтобы прочитать результат. Политика организации также может требовать одобрения до
запуска сессии; сначала одобряющий должен принять этот запрос.

## 5. Остановите и возобновите

Выберите **Остановить** для сессии и подтвердите, если это потребуется. Процесс
инструмента завершится; разговор сохранится. Выберите **Возобновить** для той же
сессии и отправьте другое сообщение. При возобновлении сохраняются выбранный
профиль, учётная запись и папка, и проверяется, что они всё ещё доступны.

Для постоянной работы, интерфейса командной строки и необязательных настроек
профиля см. [Управление сессией провайдера](/how-to/operate-provider-sessions/).

## Сообщения при нативном запуске

Другие способы установки имеют собственные ограничения проверки; см.
[Установка](https://github.com/olivaresai/olivares/blob/main/INSTALL.md#installation-qualification).
При нативном быстром запуске выводятся адрес консоли и следующий шаг для его
состояния настройки. Ниже приведены сообщения для новой установки, повторного входа
и ожидающей настройки:

```text
Next: Open the console; it guides setup, sign-in and your first session.
Next: Open the console and sign in to continue your work.
Next: Open the console to finish setup with the one-time token issued earlier.
```

Если на уровне хоста не настроен учётные данные для вывода, журнал запуска движка
содержит:

```text
session runtime: no inference credential source configured; stream-json launches are deny-closed
```

Это ограничивает профили Claude с управляемой инжекцией без привязанного
провайдера. Ключ привязанного провайдера или авторизованный вход инструмента —
отдельный источник учётных данных; см.
[Управление сессией провайдера](/how-to/operate-provider-sessions/#choose-how-the-tool-connects).
