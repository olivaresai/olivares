Аудитор может спросить, что политика **решила** в прошлую дату. Плоскость
управления отвечает из **журнала свидетельств**: записанной версии
политики и входов того решения. Она **не** оценивает политику,
активную сегодня.

## Команда

```bash
olivares policy replay \
  --at 2026-09-15T12:00:00Z \
  --principal agent-7 \
  --resource public.customers \
  --resource-kind postgres.table \
  --action SELECT
```

Или одна сохранённая строка:

```bash
olivares policy replay --decision-id <decision-id> -o json
```

HTTP: `POST /v1/m/governance/decisions/replay` и
`GET /v1/m/governance/decisions/{id}/reconstruct`. В этой поставке нет
кнопки консоли. Используйте CLI или HTTP.

## Что доказывает реконструкция

Статус `reconstructed` означает: записано `live_authorization`; названный
артефакт **сохранён**; этот двоичный файл может выполнить оценщик
(Cedar); переоценка использует **исходный** артефакт; живой PDP **не**
читался.

`policy_version_id` — идентификатор артефакта. Это не `PolicyVersion`
свидетеля маршрута и не номер ревизии автора.

## Чего она не доказывает

- Честность исходной точки исполнения. Сохранённый allow не разрешает
  повторить эффект.
- Подлинность производителя и целостность цепи.
- Внешнюю активность без решения Olivares: ответ —
  `COULD NOT RECONSTRUCT`.
- Движки, которые этот двоичный файл не выполняет (OPA/Rego только
  для составления).

## COULD NOT RECONSTRUCT

```
COULD NOT RECONSTRUCT
missing: authorization_decision
```

`missing` называет отсутствующий факт. Старые строки остаются
**unknown**; хранилище не заполняет их из текущей политики.

## Понедельник, вторник, среда

Понедельник: записать allow. Вторник: отозвать. Среда: `--at <понедельник>`
по-прежнему отвечает **allow** из артефакта понедельника.
