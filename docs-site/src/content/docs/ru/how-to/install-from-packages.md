:::note[Опубликованные имена пакетов]
Выпуск v26.9.1 на GitHub публикует артефакты `.deb`, `.rpm` и `.apk` для `amd64` и
`arm64`, вместе с `checksums.txt`, `checksums.txt.sig` и `checksums.txt.pem`. Команды
ниже используют буквальные имена `amd64` этого выпуска; на 64-битном ARM-узле замените
`amd64` на `arm64`. Устанавливайте из этих проверенных артефактов выпуска.
Производители метаданных репозитория в дереве исходников не являются инструкциями по
установке для этого руководства.

**Квалификация DIST-24-05.** CI квалифицирует проверенный **shell-установщик** и его
контракт службы/doctor, а не `dpkg`, `rpm` или `apk`: матрица dispatch/pull request
запускает его против опубликованного выпуска в контейнерных userland Debian
stable, Ubuntu 24.04 LTS, Fedora, openSUSE Leap и Alpine и на размещённом раннере macOS
14, и завершается как «неизмеримо», когда публичный выпуск недоступен, вместо того чтобы
засчитывать dry-run как покрытие. Эта матрица не сертифицирует нативную установку через
пакетный менеджер. Нативный жизненный цикл пакетов, собранных из этого исходного дерева, —
установка, запуск, перезапуск, обновление работающей службы OpenRC и снятие — был
выполнен локально в одноразовом госте Alpine; это свидетельство для этого дерева, а не
подписанная, размещённая или preproduction-квалификация, которая остаётся невыполненной.

**Предлагаемые репозитории DIST-24-06 (не действующая поверхность установки).**
Исходное дерево содержит детерминированные производители репозиториев apt, rpm-md и APK,
проверяльщик подписанных индексов, квалификацию чистого клиента и поэтапный рабочий
процесс публикации, чей dispatch остаётся инертным, пока его не одобрит рецензент.
**Ни один URL репозитория пакетов не действует**, ни одно имя DNS не делегировано и ни
один производственный ключ подписи репозитория не выделен. Ничто в этом предложении не
является источником для пакетного менеджера; продолжайте использовать проверенные
артефакты выпуска ниже.
:::

Это путь для обычного Linux-узла, где движок должен работать как служба, а не в
контейнере. Debian/Ubuntu и RHEL/Fedora/SUSE по умолчанию используют **systemd**.
Init Alpine по умолчанию — **OpenRC**, не systemd. Для контейнеров см.
[Развёртывание с Docker](/ru/how-to/docker-deployment/); для узла без исходящего
маршрута —
[Установка в изолированной среде](/ru/how-to/air-gap-install/), на которую эта
страница ссылается на шаге обновления.

## 1. Проверьте выпуск, прежде чем ему доверять

Для продукта безопасности конвейер сборки — часть модели доверия, поэтому здесь никто
не просит принять загрузку на веру. Положите пакет, `checksums.txt` и подпись в один
каталог и запустите проверяющий **из этого каталога**:

```bash
# keyless / Sigstore (default; reaches Rekor over the network)
./verify-release.sh
```

Релизы подписываются без ключа и не публикуют публичный ключ cosign, поэтому для пакетов,
скачанных из релиза, используйте команду без ключа. Ей нужен корневой материал доверия Sigstore,
который cosign загружает, если он ещё не в кэше. `--offline` убирает только обращение к Rekor и не
превращает проверку в работу без сети. `--key` предназначен только для файлов, подписанных
закрытым ключом под вашим контролем, и этот публичный ключ нужно получить отдельно от
проверяемых файлов.

Что проверяет каждый шаг, как он ведёт себя на частичном выпуске и как вместо этого
проверить образ контейнера — в
[Проверьте то, что скачали](/ru/how-to/verify-a-release/).

## 2. Установите пакет

Три формата несут двоичный файл в `/usr/bin/olivares`, файл окружения в
`/etc/olivares/olivares.env` (`config|noreplace`), каталог данных
`/var/lib/olivares` и тексты лицензий. `.deb` и `.rpm` поставляют укреплённый
**systemd**-юнит. **Пакеты из этого исходного дерева** кладут в `.apk` исполняемый
юнит **OpenRC** в `/etc/init.d/olivares` с явным штампом `package-init`, чтобы хуки не
угадывали по наличию `systemctl` на узле.

Ранее опубликованный `.apk` поставлял тот же systemd-юнит и **не** поставлял юнит
OpenRC. Тот опубликованный linux-tar несёт тексты лицензий, README и `SECURITY.md`;
он не включает `scripts/install-service.sh` и `packaging/service/`. Эти файлы-адаптеры
находятся в подписанном архиве дерева для следующего выпуска.

```bash
# Debian / Ubuntu
sudo dpkg -i olivares_26.9.1_linux_amd64.deb

# RHEL / Fedora / SUSE
sudo rpm -Uvh olivares_26.9.1_linux_amd64.rpm

# Alpine
sudo apk add --allow-untrusted olivares_26.9.1_linux_amd64.apk
```

Установка **создаёт системного пользователя и группу `olivares`** (оболочка
`/usr/sbin/nologin`, домашний каталог `/var/lib/olivares`), создаёт `/var/lib/olivares`
с режимом `0750` во владении этого пользователя и создаёт `/etc/olivares`.
systemd-пакеты перезагружают systemd, когда есть `systemctl`; пакеты OpenRC не включают
и не запускают службу. Он **ничего не запускает** — см.
[чего пакет не делает](#8-чего-пакет-не-делает).

### Запуск движка

На Debian/Ubuntu и RHEL/Fedora/SUSE:

```bash
sudo systemctl enable --now olivares
```

На **OpenRC** (`.apk` из этого исходного дерева):

```bash
sudo rc-service olivares start
# необязательно; пакет этого не делает:
sudo rc-update add olivares default
```

Токен первого запуска находится в `/var/log/olivares.log` (и в `logread`, если работает
syslogd). Дополнительные флаги из `OLIVARES_EXTRA_ARGS` добавляются с отключённым
globbing и разбиваются по пробелам; вложенные кавычки не интерпретируются, а файл
окружения не исполняется как shell.

На **ранее опубликованном Alpine** нет `systemctl`, и у того `.apk` нет юнита
OpenRC. Запустите движок от служебного пользователя; токен первого запуска
печатается в stdout:

```bash
sudo -u olivares olivares serve --data-dir=/var/lib/olivares \
  --listen=:8443 --grpc-listen=:8444 --checkpoint-interval=1h
```

## 3. Укреплённый systemd-юнит

Упакованный systemd-юнит запускает движок от непривилегированного пользователя
`olivares` с пустым bounding-набором capabilities — он не держит ни ambient, ни
bounding capabilities — и `NoNewPrivileges=true`, так что ничто из запущенного им не
может их получить. Сверху он несёт `ProtectSystem=strict` (файловая система только для
чтения, кроме `ReadWritePaths=/var/lib/olivares`), `ProtectHome`, `PrivateTmp`,
`PrivateDevices`, четыре директивы `ProtectKernel*`/`ProtectClock`,
`RestrictNamespaces`, `RestrictSUIDSGID`, `RestrictRealtime`, `LockPersonality`,
`MemoryDenyWriteExecute`, `SystemCallArchitectures=native`, фильтр системных вызовов
`@system-service`, дополнительно отбрасывающий `@privileged` и `@resources`, и
`UMask=0027`.

На Alpine по умолчанию эти директивы systemd не применяются к **ранее опубликованному**
`.apk`, потому что systemd-юнит этой полезной нагрузки не запущен. Пакеты
`.apk`, собранные из этого исходного дерева, вместо этого работают под OpenRC: они
используют учётную запись `olivares`, пишут токен первого запуска в
`/var/log/olivares.log` и не реализуют директивы песочницы systemd.

**Слушатели по умолчанию принимают соединения из сети** — `--listen=:8443` для HTTP
(REST плюс встроенная консоль) и `--grpc-listen=:8444` для gRPC, dual-stack-шаблон. Это
сервер, и защищают его включённый TLS, отсутствие учётных данных по умолчанию и
одноразовый токен настройки. Ограничивайте их намеренно через
`OLIVARES_EXTRA_ARGS=--listen=127.0.0.1:8443 --grpc-listen=127.0.0.1:8444` в
`/etc/olivares/olivares.env` — эти флаги добавляются после собственных флагов юнита, и
побеждает последний — и поставьте перед ними собственное завершение TLS. Для IPv6
loopback используйте `--listen=[::1]:8443`.

### Исполняемый scratch-раздел

Это сбой, который стоит знать заранее на systemd-узле, потому что симптом не называет
причину.

Внепроцессные коннекторы первой стороны поставляются **встроенными в двоичный файл**.
При загрузке движок извлекает нужные во частный scratch и исполняет их как
подпроцессы. Если `TMPDIR` не задан, scratch создаётся под `<data-dir>/tmp`; только
незаписываемый каталог данных заставляет движок упасть в системный временный каталог.
Явный `TMPDIR` всегда побеждает.

Поэтому упакованная systemd-служба по умолчанию использует `/var/lib/olivares/tmp`, а
не `/tmp`. Проверьте раздел, который реально будет держать исполняемый scratch:

```bash
check_scratch_mount() {
  target=${1:-/var/lib/olivares}
  opts=$(findmnt -no OPTIONS --target "$target") || {
    printf '%s\n' "cannot read mount options for $target (missing path or permission)" >&2
    return 1
  }
  [ -n "$opts" ] || {
    printf '%s\n' "mount options for $target are unknown" >&2
    return 1
  }
  case ",$opts," in
    *,noexec,*) printf '%s\n' 'noexec — set TMPDIR' ;;
    *) printf '%s\n' 'exec-capable — nothing to do' ;;
  esac
}
check_scratch_mount /var/lib/olivares
```

Если там `noexec`, направьте `TMPDIR` на каталог, записываемый при
`ProtectSystem=strict` **и** лежащий на разделе, допускающем исполнение:

```bash
sudo install -d -o olivares -g olivares -m 0750 /run/olivares-exec-tmp
sudo systemctl edit olivares      # creates a drop-in; do not edit the shipped unit
```

```ini
[Service]
Environment=TMPDIR=/run/olivares-exec-tmp
ReadWritePaths=/run/olivares-exec-tmp
```

Затем перезапустите. Если exec отвергнут с `EACCES` или `ENOEXEC`, ошибка движка
называет раздел извлечения и два органа перемещения (`TMPDIR` и data-dir); она не
сообщает о noexec-разделе как об отсутствующем коннекторе.

Используйте `systemctl edit`, никогда прямое редактирование
`/usr/lib/systemd/system/olivares.service`: этот файл принадлежит пакету, и обновление
его заменяет.

## 4. Первый запуск: `olivares quickstart`

`quickstart` — это `serve` с дружелюбными значениями по умолчанию и направляющим
баннером. Он никогда не изобретает учётные данные по умолчанию; он указывает на
встроенную консоль, чтобы создать первого администратора с **одноразовым токеном**.

Если вы уже обслуживаете под упакованным systemd-юнитом, не запускайте `quickstart` —
**токен настройки первого запуска печатается в журнал**:

```bash
journalctl -u olivares | sed -n '/FIRST-BOOT SETUP/,/========================/p'
```

Если вы запустили `serve` на переднем плане (Alpine по умолчанию), тот же баннер — в
stdout.

Откройте консоль по `https://127.0.0.1:8443` (при первом запуске генерируется
самоподписанный сертификат), предъявите этот токен и создайте администратора. Токен
одноразовый.

На рабочей станции, чтобы осмотреться без установки службы, `olivares quickstart`
делает то же самое на переднем плане с `--listen`/`--grpc-listen`/`--data-dir`, если
нужно уйти от значений по умолчанию.

## 5. Первый источник: pgAudit

Источник — это место, откуда движок принимает наблюдения. Глаголы разделены по тому,
чего стоит каждый, и их стоит использовать в этом порядке: `plan` говорит, что
изменилось бы, и ничего не пишет, `validate` говорит, что конфигурация согласована
сама по себе **без обращения к сети**, `test` реально открывает источник, чтобы
доказать, что он отвечает, а `set` применяет. Конфигурация несёт **ссылки** на секреты
(`store:<name>`), никогда значения.

pgAudit читает журнал аудита PostgreSQL, поэтому `log_path` — единственное
обязательное поле:

```bash
# coherent by itself? (writes nothing, opens no socket)
sudo -u olivares olivares sources validate --name pg-prod --kind pgaudit \
  --tenant <your-tenant-id> \
  --config log_path=/var/log/postgresql/postgresql.log \
  --data-dir /var/lib/olivares

# does it actually answer? (opens the source for real)
sudo -u olivares olivares sources test --name pg-prod --kind pgaudit \
  --tenant <your-tenant-id> \
  --config log_path=/var/log/postgresql/postgresql.log \
  --data-dir /var/lib/olivares

# apply it
sudo -u olivares olivares sources set --name pg-prod --kind pgaudit \
  --tenant <your-tenant-id> \
  --config log_path=/var/log/postgresql/postgresql.log \
  --actor "$(id -un)" --reason "onboard the production audit log" \
  --data-dir /var/lib/olivares
```

Три вещи в командной строке выше — не наполнитель:

- **`--tenant` обязателен.** Источник должен назвать делового арендатора, которому
  принадлежат наблюдения; без него команда отказывается, а не угадывает владельца
  аудиторских данных.
- **`--actor` и `--reason` требует `set`, и только `set`.** Привилегированная
  офлайн-операция должна записать, кто её выполнил и зачем. `validate` не нуждается ни
  в одном, потому что ничего не пишет — асимметрия и есть смысл.
- **`format` по умолчанию `csvlog`, а `follow` — `true`**, поэтому стандартному
  развёртыванию pgAudit не нужно ни то ни другое.

Применение печатает, что изменилось, поле за полем, и говорит, как заставить
**работающий** движок подхватить это без перезапуска —
`POST /v1/console/runtime/reload` или `SIGHUP`. Под упакованным systemd-юнитом это
`sudo systemctl reload olivares`. Если вы запустили `serve` на переднем плане,
отправьте `SIGHUP` этому процессу.

Служебному пользователю нужен доступ на чтение к этому файлу журнала; в большинстве
дистрибутивов это значит добавить `olivares` в группу `adm` или `postgres` —
намеренная выдача с вашей стороны, а не то, что пакет делает за вас.

## 6. Обновление

`olivares upgrade` заменяет двоичный файл на месте, и свойства безопасности — причина
предпочесть это ручной переустановке пакета: он **никогда не заменяет двоичный файл,
пока скачанный кандидат не прошёл успешный exec-зонд**, хранит резервную копию с
меткой времени и **возвращается к этой копии, если зонд после замены не проходит**.

```bash
sudo olivares upgrade --check    # what would change, without changing anything
sudo olivares upgrade --yes      # do it
```

Три флага особенно важны для пакетной установки:

- **`--endpoint`** — брать обновления из репозитория GitHub, которым вы управляете,
  а не из значения по умолчанию. Это выход для зеркала или форка.
- **`--bundle`** — установить из локального каталога бандла или `.tar.gz` **без сети
  вообще**. Собрать этот бандл и перенести его описано в
  [Установка в изолированной среде](/ru/how-to/air-gap-install/).
- **`--install-timer`** — выдать **необязательный systemd**-таймер и службу, которые
  проверяют обновления по расписанию. Ничто не ставит это за вас; см.
  [чего пакет не делает](#8-чего-пакет-не-делает). Это генератор systemd.

Учтите, что постановка и exec-зонд происходят **в каталоге установки, рядом с целью —
не в `/tmp`**, поэтому раздел `noexec`, обсуждённый
[выше](#исполняемый-scratch-раздел), не ломает обновление. Раздел `noexec` на
каталоге **установки** — другое дело и делает установленную версию неизмеримой; этот
случай, каналы выпуска, поэтапный выкат и откат — в
[Обновление и откат](/ru/how-to/upgrade-and-rollback/).

## 7. Удалить или перенести, не угадывая пути

Пакет записывает `/var/lib/olivares/install-manifest.json`. Деинсталлятор проверяет
полный манифест по подписанному индексу дистрибуции, прежде чем трогать службу или
файловую систему; неожиданный путь возвращает 2. Сначала осмотрите, затем явно
выберите сохранение:

```bash
sudo olivares uninstall --plan --data-dir /var/lib/olivares
sudo olivares uninstall --preserve --data-dir /var/lib/olivares
sudo olivares uninstall --purge --data-dir /var/lib/olivares --yes
```

Preserve — политика снятия пакета: она сохраняет конфигурацию, данные, журналы, ключи
и их служебную идентичность. В systemd-пакетах хук снятия выполняет `--preserve`. В
OpenRC-пакетах `.apk`, собранных из этого исходного дерева, хук останавливает службу,
если она активна, снимает запись из runlevel по умолчанию, не завершаясь ошибкой, если её
никогда не включали, проверяет полный манифест через `--plan` и даёт apk удалить файлы,
принадлежащие пакету. Ранее опубликованные пакеты Alpine проверяли только через
`--plan`, потому что у той полезной нагрузки не было юнита OpenRC, который нужно
остановить. Запускайте
`--purge` перед снятием пакета только когда намерение — стереть. Требуется
подтверждение, удаляются только проиндексированные пути.

Для переезда хозяйства сначала создайте `olivares dr backup`, установите назначение и
выполните там `olivares dr restore`. Текущие бандлы используют `hmac-sha256-kek-v1`
для аутентификации манифеста и каждой нагрузки под вашим KEK. Экспорт более нового
движка отклоняется до записей; отдельно аутентифицированный бандл pre-v26.9 явно
требует `--allow-legacy-unsigned`.
[Руководство по резервному копированию и восстановлению](/ru/how-to/backup-and-restore/)
охватывает хранение KEK и доказательство непрерывности после импорта.

## 8. Чего пакет не делает

Сказано прямо, потому что продукт безопасности, который здесь расплывчат, не заслуживает
установки:

- **Он не добавляет репозиторий.** Ничего не пишется в `/etc/apt/sources.list.d`,
  `/etc/yum.repos.d` или `/etc/apk/repositories`. Вы установили один файл; установлен
  был только этот файл. Обновления запускаете вы — новым пакетом или
  `olivares upgrade`.
- **Он не запускает и не включает службу.** systemd-пакеты перезагружают systemd,
  когда есть `systemctl`, и печатают `systemctl enable --now`. Пакеты OpenRC печатают
  `rc-service olivares start` и не выполняют `rc-update add`. Запуск остаётся вашим
  решением. Обновление уже работающей службы OpenRC останавливает её, заменяет файлы и
  запускает снова; неактивная служба остаётся неактивной.
- **Проверка лицензии никому не звонит. Загрузка того, за что вы заплатили, — да.**
  Проверка лицензии в открытой сборке — офлайн Ed25519, удалённого выключателя нет, и
  никакой лицензионный ключ не ограничивает и не ухудшает эту сборку — сборка AGPL и
  есть вся платформа.
  **Нет обязательной телеметрии и исходящего трафика плоскости управления по
  умолчанию: границу пересекает то, что вы настроили пересекать** — вызовы ваших
  API моделей, выходы SIEM/webhook, которые вы подключили, внешний поставщик
  эмбеддингов, если вы его подготовили, и любой источник, который опрашивает
  коннектор (его `addr`, `base_url` или `endpoint`) с заданным вами интервалом.
- **Но `olivares upgrade` сознательно делает сетевой вызов, когда вы его
  запускаете** — в этом смысл проверки обновлений, и `--check` показывает план, пока
  ничего не сдвинулось. Честная форма обещания: *проверка лицензии никому не звонит;
  загрузка того, за что вы заплатили, — да.* Используйте `--bundle`, если путь
  обновления тоже не должен делать вызовов.
- **Он открывает порт в сеть.** Юнит слушает все интерфейсы, пока вы сами его не
  расширите.
