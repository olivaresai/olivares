# -----------------------------------------------------------------------------
# ⛔ POR QUÉ ESTE FICHERO EXISTE, y qué se servía antes de él. Medido el 2026-09-01:
# `https://docs.olivares.ai/robots.txt` respondía 200 con 1248 bytes, 24 líneas y
# CERO directivas — ni un `User-agent:`, ni un `Allow:`, ni un `Disallow:`, ni un
# `Sitemap:`. No era nuestro: era el fichero de "content signals" que Cloudflare
# inyecta cuando el origen no sirve ninguno. Aquí no había `robots.txt`.
#
# Las dos consecuencias, y la segunda es la que importa:
#
#   1. El sitemap de este sitio (2156 URLs) no se anunciaba en ninguna parte, y
#      apenas se enlazaba desde el sitio principal. Descubrimiento por casualidad.
#
#   2. La postura anti-entrenamiento que `olivares.ai` aplica con cuidado NO regía
#      aquí. El sitio principal bloquea con `Disallow: /` a veinte rastreadores de
#      entrenamiento — se puede comprobar en `https://olivares.ai/robots.txt` —; en
#      este subdominio no regía ninguna de esas líneas, así que las 2156 páginas de
#      documentación de producto, la superficie técnica más valiosa que publicamos,
#      estaban abiertas a todos ellos.
#
# Esto NO decide nada nuevo: aplica aquí la política que el proyecto ya tiene
# firmada allí. La lista de abajo es la MISMA, en el mismo orden.
#
# CONTROL POSITIVO de que publicar este fichero surte efecto, medido antes de
# escribirlo: `https://olivares.ai/robots.txt` devuelve exactamente los bytes que
# su repositorio tiene en disco, sin rastro del preámbulo de "content signals".
# ⇒ Cloudflare sólo inyecta el suyo cuando el origen no sirve ninguno.
#
# `scripts/check-robots.mjs` lo vigila sobre `dist/`, que es lo que se despliega:
# un fichero en `public/` es una promesa que sólo se cumple si el build la copia.
#
# Un user-agent con grupo propio lee SÓLO su grupo, así que las reglas por bot de
# abajo anulan el grupo genérico.
