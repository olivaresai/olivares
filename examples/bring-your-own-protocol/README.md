# Bring Your Own Protocol: FabWorks ERP

This example shows the customer story: "we have an in-house ERP with a
proprietary REST-ish protocol; make it a governed content source in hours."
The protocol, company and data are fictional.

What is here:

- `erp-fixture/` serves the invented FabWorks ERP JSON protocol with documents,
  per-document group ACL references and a change feed.
- `fabworks-connector/` is the `content-source` archetype generated by
  `olivares connector init`, then filled in at the `FABWORKS-FILL` markers.
- `admission-check/` is a stdlib-only offline helper used by `smoke.sh` to sign
  the plugin binary and prove no-anchor admission refuses.
- `smoke.sh` runs the full local loop without network access.

## 1. Init

From the repository checkout:

```sh
go run ./cmd/olivares connector init acme.fabworks-erp \
  --dir examples/bring-your-own-protocol/fabworks-connector \
  --module example.com/fabworks/olivares-connector-fabworks-erp \
  --template content-source \
  --sdk-path "$PWD/sdk"
```

The generated connector implements `sdk.ContentSource`, declares the
`knowledge.document` surface and serves as a go-plugin binary through
`plugin.ServeContentSource`.

## 2. Implement

The only filled code is the protocol adapter between the `FABWORKS-FILL START`
and `FABWORKS-FILL END` comments in `fabworks-connector/fabworkserp.go`.
It maps the fictional endpoints to the SDK:

- `GET /fw/v1/documents` -> `List`
- `GET /fw/v1/documents/{id}` -> `Fetch`
- `GET /fw/v1/changes` -> `DeltaList`
- `GET /fw/v1/documents/{id}/acl` -> `FetchACL`

ACLs are permission references such as `group:engineering`, never credential
material. Empty ACLs would inherit the KB default. The connector contains no
governance code; it only returns content, provenance and ACL references.

## 3. Test

```sh
cd examples/bring-your-own-protocol/erp-fixture
GOWORK=off GOMAXPROCS=2 GOFLAGS=-p=1 go test ./...

cd ../fabworks-connector
GOWORK=off GOMAXPROCS=2 GOFLAGS=-p=1 go test ./...
./scripts/check-boundary.sh
```

The connector boundary check fails if the build graph imports
`github.com/olivaresai/olivares/core`.

## 4. Sign

The smoke script uses a bare Ed25519 key and a DSSE/Sigstore-shaped bundle for
the offline dev loop:

```sh
GOMAXPROCS=2 GOFLAGS=-p=1 ./examples/bring-your-own-protocol/smoke.sh
```

It builds the plugin, writes a bundle, proves the deny-closed no-anchor case is
refused, then proves the same artifact is admitted when the operator trusts the
generated public key and pins the matching sha256.

## 5. Configure

Operators pin trust globally and the plugin artifact per source:

```json
{
  "connector_trust": {
    "trusted_keys": ["-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----\n"],
    "allowed_predicates": ["https://slsa.dev/provenance/v1"]
  },
  "documents": [
    {
      "name": "fabworks-erp",
      "plugin": {
        "path": "/opt/olivares/plugins/acme-fabworks-erp",
        "sha256": "<hex sha256>",
        "bundle": "/opt/olivares/plugins/acme-fabworks-erp.sigstore.json"
      },
      "config": {
        "base_url": "https://erp.internal.example",
        "token": "store:fabworks-erp-token"
      }
    }
  ]
}
```

Unsigned, digest-mismatched or untrusted plugins are not wired.

## 6. Governed

Private connectors are first-class: a connector can stay inside one enterprise,
never be published and never appear in any public listing, and still be governed
when the operator pins its binary digest and trust root. The verified-connectors
index is a certification trail, not a trust root.

Governance is engine-side by construction. The engine keys controls on the
configured source identity, applies source scoping, ACL intersection,
retrieval content scanning and audit, and records lineage. The connector does
zero extra work beyond returning the SDK data it promised.
